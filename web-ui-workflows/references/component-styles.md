# 组件样式：选择、应用与回读

设计、修改或审核组件时使用本档；普通的“分析并改善这个 Web UI”也包含目标页面中相关组件及其实际状态，不要求用户先指出样式差异。范围仍由原任务决定。本档维护共享方法，组件定义、可选变体和公开默认由 Prompt Planet 的组件目录维护；它不要求整页逐组件拼装。

## 从用途找到同一份定义

从页面的实际用途识别组件，再取得当前目录 `/api/webui/components/v1/index.json`；默认站点为 `https://prompts.aiplanet.live`，浏览入口为 `/webui/`。用户给定开发快照或本地候选时用其同版 API，记录实际来源，不把未发布候选写成公网现状。目录 `content_sha256` 由完整有效定义计算，用于绑定本次选择、应用与审核。目录包含的 `inherited_rules` 与变体 `rules` 一起消费，不能只看预览图片。

角色依据交互和任务关系匹配，不按标题关键词或相同 HTML 标签机械匹配。对象分组的展开内容需要可持续辨认的归属范围；正文辅助详情需要延续阅读关系。两者可以采用不同呈现。相同用途、同等层级的实例应有一致的视觉含义；确需差异时，说明哪个内容或任务关系要求它，而不是把现有 CSS 差异当作理由。

同时发现本次明确选择、项目有效设计中明确的组件选择及使用者提供的本地覆盖。已有主题的派生外观不算明确组件选择；没有选择文件不等于没有项目设计记录。已有明确设计先迁入或关联同一份记录，不另造相互冲突的配置。只审核时读取并报告，不修改选择。

## 有效选择及范围

用户当前明确要求和项目硬约束是边界。同一角色的显式选择依次为：本次 `task` → 项目 `project` → 使用者本地 `user` → 目录公开默认 `public_default`。选择只覆盖该角色的视觉规则，颜色、字体与密度适配已选整站主题；未定义属性沿现有风格或场景。场景结构、业务交互与硬约束继续由其原依据维护。确有无法兼容的要求才交用户裁决。

| 用户选择 | 权威位置与完成含义 |
| --- | --- |
| 本次使用 | 本次上下文/有效设计；不自动写入项目或长期默认 |
| 当前项目使用 | 项目已有设计配置或记录；之后同项目任务重新读取 |
| 修改公开的长期默认 | 模板仓当前组件定义的 `default_variant`；按该仓构建与发布流程同步，发布前仍是候选 |
| 使用者自行保留本地覆盖 | 宿主明确配置路径；不上传，也不声称网站公开默认已改变 |

取消覆盖只删除指定层的选择，再显示下一适用来源。未知组件或变体必须显式报告并修正引用或取消该条，不能默选首项或以公开默认掩盖失效覆盖。目录内容相较上次选择变化时重新核对相关规则及目标状态；hash 不同是需要重核的信号，不证明样式必然变化。没有匹配角色时继续项目有效设计，不强塞最相近的组件。

网站显示的“默认”仅指该版本目录的公开默认；未经目标项目回读，不能显示或声称“你的项目当前采用”。复制请求只说明请求已生成，保存选择只说明配置已改变，两者都不证明页面采用。

## 应用与核验是一条路径

将角色、变体、来源、范围和实际目录身份纳入同一份有效设计，供实现与审核共同使用。按定义实现目标产品的完整交互单元，再从真实入口操作：触发区、变化后的主体、嵌套内容、结束位置和相邻操作共同决定读者能否理解；只检查收起态、颜色变量或单个元素不够。

在目标状态中并排比较同用途的实例，追踪外部边界、表面层级和所属内容到结束位置；同时保留因用途不同而正确存在的差异。按页面实际内容检查长内容、窄屏和键盘操作，不以静态类名相同替代视觉观察。发现差异后沿实际内容和共享 renderer 核原因，在授权内修复，再回到原失败状态与另一个相关实例复验。新组件及首次采用的变体也走相同路径。

完成后回读权威配置/有效设计并实际查看页面，分别报告“保存的选择”“实际采用的来源与变体”“已操作的页面状态”和未核实项。目标包含产品修改时不能停在选择记录或复制按钮。普通审查未获修改授权时给出具体发现及修正方向。

## 可移植解析工具

随包 [component_styles.py](../scripts/component_styles.py) 仅处理显式本地文件，不发网络请求、不修改产品页面、不发布默认。先用宿主已获授权的读取方式取得完整目录 API；开发版沿其原有读取边界，不扩凭据权限。项目配置复用已有位置；无机器配置时可在项目设计目录保存一份组件选择文件，并让项目入口指向它。使用 Python 3 运行本包脚本，不要求作者的 home 或仓库。

配置形状为 `{"schema_version":1,"components":{"组件 ID":{"variant":"变体 ID","catalog_sha256":"本次目录摘要"}}}`。工具保留其它顶层字段；`catalog_sha256` 记录选择时所据目录，解析时使用当前实际目录。显式 `--project`、`--user`、`--task` 只读取调用者提供的文件；缺失或格式错误不被解释成无覆盖。首次 `select` 可以创建所选保存路径。`--task` 是同形本次输入文件，不是全局配置。

| 动作 | 调用形式（将占位参数换成本次实际值） |
| --- | --- |
| 读取/验证有效选择 | `python3 <本包>/scripts/component_styles.py resolve --catalog <目录文件> --project <项目配置> --json` |
| 本次选择 | `python3 <本包>/scripts/component_styles.py select --catalog <目录文件> --component <组件> --variant <变体> --scope task --json` |
| 保存项目覆盖并回读 | `python3 <本包>/scripts/component_styles.py select --catalog <目录文件> --component <组件> --variant <变体> --scope project --project <项目配置> --json` |
| 取消项目覆盖并回读 | `python3 <本包>/scripts/component_styles.py clear --catalog <目录文件> --component <组件> --scope project --project <项目配置> --json` |
| 独立重新回读 | `python3 <本包>/scripts/component_styles.py readback --catalog <目录文件> --project <项目配置> --json` |

没有相应覆盖文件时省略该层参数；传入的文件须是实际读取对象。`select --scope task` 只返回本次选择数据，由本次上下文消费；`clear --scope task` 返回取消指定组件后的本次覆盖（传入 `--task` 时保留其它条目），用返回值更新本次上下文后重新解析其它层。`--scope user --user <明确路径>` 用于使用者主动选择的本地覆盖，不能冒充公开长期默认。`--scope default`（兼容 `public-default`） 只提示目录发布路径并返回未执行，不改变网站或本地默认。工具写同一文件时使用稳定锁和原子替换；它不约束外部编辑器，实际并发开发仍遵守宿主的隔离方式。

目录无法取得时保留原来源与失败事实；已有明确要求及已验证本地定义仍可支持授权内工作，但标明所据版本和未取得当前公开目录。不得编造默认、静默换未批准风格，或因目录一时不可读停止不依赖它的已知缺陷修复。

## 从参照扩充选择

先在现有角色和变体中查是否已有适用表达；研究真实参照的相关状态，区分实际观察与设计推导。可借鉴的规则、适用边界与可操作示例进入模板仓的同一当前定义；引用整套风格已有组件描述时保留引用关系，不复制第二份权威。候选先通过同一浏览、选择、应用与回读路径，新增替代不自动改默认。公开内容和默认的批准、发布沿库的既有流程；单一产品效果不等于跨项目审美批准。
