# 启发式评分指南

对 Nielsen 十大可用性启发式原则，先按本次对象与读者任务判断适用性，再依据实际观察评分。下列检查点是判断线索，不要求每个页面或组件具备全部能力。

| 判定 | 记录方式 |
|---|---|
| 适用且已有足够观察 | 以 0–4 分记录表现及证据；4 分意味着确实出色 |
| 对本次对象不适用 | 标记“不适用”并说明理由，不因缺少无关能力扣分 |
| 适用但证据不足 | 标记“未观察”并说明缺口，不猜分，也不当作不适用 |

## Nielsen 十大启发式原则

### 1. 系统状态的可见性

通过及时、恰当的反馈让用户知道正在发生什么。

**检查**：
- 异步操作期间的加载指示
- 用户动作的确认（保存、提交、删除）
- 多步流程的进度指示
- 导航中的当前位置（面包屑、激活态）
- 表单校验反馈（内联，而不是只在提交时）

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 没有反馈——用户只能猜发生了什么 |
| 1 | 罕有反馈——多数动作没有可见响应 |
| 2 | 部分——有些状态传达了，仍有重大缺口 |
| 3 | 良好——多数操作给出清晰反馈，缺口轻微 |
| 4 | 出色——每个动作都有确认，进度始终可见 |

### 2. 系统与真实世界的匹配

说用户的语言。遵循真实世界的惯例。信息以自然、合乎逻辑的顺序出现。

**检查**：
- 熟悉的术语（没有未加解释的行话）
- 符合用户预期的合乎逻辑的信息顺序
- 可辨识的图标与隐喻
- 对目标受众而言合适的领域语言
- 自然的阅读流（从左到右、自上而下的优先级）

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 纯技术行话，对用户而言完全陌生 |
| 1 | 大体上令人困惑——要有领域专业知识才走得通 |
| 2 | 混杂——部分是平实语言，部分行话漏了出来 |
| 3 | 大体自然——偶有术语需要上下文 |
| 4 | 全程流利地说着用户的语言 |

### 3. 用户的控制权与自由度

用户需要一个清晰的"紧急出口"，无需冗长对话就能脱离非预期状态。

**检查**：
- 撤销/重做功能
- 表单与弹窗上的取消按钮
- 清晰地导航回安全处（首页、上一步）
- 便捷地清除筛选、搜索、选择的方式
- 从冗长或多步流程中脱身

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 用户被困住——不刷新就出不来 |
| 1 | 出口难找——必须找到隐蔽路径才能脱身 |
| 2 | 有一些出口——主流程有脱身方式，边界情况没有 |
| 3 | 控制良好——用户能退出并撤销多数动作 |
| 4 | 完全可控——撤销、取消、返回、脱身处处都有 |

### 4. 一致性与标准

用户不该去琢磨不同的词、情境或动作是否是同一个意思。

**检查**：
- 整个界面术语一致
- 相同动作在各处产生相同结果
- 遵循平台惯例（标准 UI 模式）
- 视觉一致性（配色、字体排印、间距、组件）
- 一致的交互模式（同一手势 = 同一行为）

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 处处不一致——像是把不同产品缝在一起 |
| 1 | 大量不一致——相似的东西看起来/行为却不同 |
| 2 | 部分一致——主流程对得上，细节发散 |
| 3 | 大体一致——偶有偏离，不至于令人困惑 |
| 4 | 完全一致——系统内聚、行为可预期 |

### 5. 错误预防

比好的错误提示更好的，是从一开始就防止问题发生的设计。

**检查**：
- 破坏性动作（删除、覆盖）之前的确认
- 防止无效输入的约束（日期选择器、下拉框）
- 能减少出错的智能默认值
- 能防止误解的清晰标签
- 自动保存与草稿恢复

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 极易出错——处处没有护栏 |
| 1 | 防护很少——部分输入有校验，多数没有 |
| 2 | 部分预防——常见错误被拦住，边界情况漏过 |
| 3 | 预防良好——多数出错路径被主动挡住 |
| 4 | 出色——靠智能约束使出错几乎不可能 |

### 6. 再认优于回忆

尽量减轻记忆负担。让对象、动作和选项可见或易于取回。

**检查**：
- 选项可见（不埋在隐藏菜单里）
- 需要时有情境化帮助（tooltip、内联提示）
- 最近项与历史记录
- 自动补全与建议
- 图标带标签（不是只有图标的导航）

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 极度依赖记忆——用户必须记住路径和命令 |
| 1 | 大体靠回忆——大量隐藏功能，可见线索很少 |
| 2 | 有一些辅助——主要动作可见，次要功能被隐藏 |
| 3 | 再认良好——多数东西可发现，几乎不需记忆 |
| 4 | 一切皆可发现——用户从不需要记忆 |

### 7. 使用的灵活性与高效性

加速器——对新手不可见——能加快专家的交互。

**检查**：
- 常用动作的键盘快捷键
- 可定制的界面元素
- 最近项与收藏
- 批量操作
- 不使基础用法复杂化的高阶用户功能

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 只有一条僵硬路径——没有快捷方式或替代方案 |
| 1 | 灵活性有限——主路径之外备选很少 |
| 2 | 有一些快捷方式——基本键盘支持，批量操作有限 |
| 3 | 加速器良好——键盘导航、部分可定制 |
| 4 | 高度灵活——多条路径、高阶功能、可定制 |

### 8. 美观与极简设计

界面不该包含无关或极少需要的信息。每个元素都应服务于某个目的。

**检查**：
- 每一步只显示必要信息
- 清晰的视觉层级在引导注意力
- 有目的地使用颜色与强调
- 没有争夺注意力的装饰性杂乱
- 聚焦、不拥挤的 layout

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 令人不知所措——所有东西平等地争夺注意力 |
| 1 | 杂乱——噪声太多，难以找到要紧的东西 |
| 2 | 有些杂乱——主内容清楚，外围嘈杂 |
| 3 | 大体干净——设计聚焦，视觉噪声轻微 |
| 4 | 完美极简——每个元素都配得上它占的像素 |

### 9. 帮助用户识别、诊断并从错误中恢复

错误提示应使用平实语言、精确指出问题，并建设性地给出解决方案。

**检查**：
- 平实语言的错误提示（不给用户看错误码）
- 具体地指明问题（"邮箱缺少 @"，而不是"输入无效"）
- 可付诸行动的恢复建议
- 错误显示在问题来源附近
- 非阻断式的错误处理（不要清空表单）

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 晦涩的错误——错误码、行话，或干脆没有提示 |
| 1 | 含糊的错误——"出错了"，没有任何指引 |
| 2 | 清楚但没用——说出了问题，没说怎么修 |
| 3 | 清楚且有建议——指明问题并给出下一步 |
| 4 | 完美恢复——精确定位问题、建议修法、保留用户的工作 |

### 10. 帮助与文档

即便系统不看文档也能用，帮助也应易于找到、以任务为中心且简洁。

**检查**：
- 可搜索的帮助或文档
- 情境化帮助（tooltip、内联提示、引导游览）
- 以任务为中心的组织方式（而不是按功能组织）
- 简洁、可扫读的内容
- 无需离开当前上下文即可便捷访问

**评分**：
| 分数 | 判据 |
|-------|----------|
| 0 | 哪里都没有帮助 |
| 1 | 帮助存在，但难找或不相关 |
| 2 | 基础帮助——有 FAQ 或文档，但不是情境化的 |
| 3 | 文档良好——可搜索、大体以任务为中心 |
| 4 | 出色的情境化帮助——在正确的时刻给出正确的信息 |

---

## 分数汇总

只有十项均适用且有足够观察时，才汇总为 `/40`；其余情况保留逐项结果并说明覆盖，不折算总分或套用评级区间。总分只描述这十项的观察表现，不能直接判定产品不可用、要求重做或决定能否发布。整改与优先级依据具体任务影响，按下文「问题严重度（P0–P3）」执行。

---

## 问题严重度（P0–P3）

先依据本次有效设计与实际任务影响确认问题成立，再按任务阻断、困难程度及重复阅读或操作成本定级。说明受影响的任务、状态、频次与可用替代路径，使严重度可追溯到实际后果：

| 优先级 | 名称 | 描述 | 处置 |
|----------|------|-------------|--------|
| **P0** | 阻断 | 完全阻止任务完成 | 立即修复——这是致命问题 |
| **P1** | 重大 | 造成显著困难或困惑 | 发布前修复 |
| **P2** | 轻微 | 增加少量阅读或操作成本，任务仍易于完成 | 下一轮修复 |
| **P3** | 打磨 | 修了更好，对用户无实质影响 | 时间允许就修 |

首屏位置、留白比例、滚动距离等读数用于解释具体任务影响，不单独决定问题成立或严重度。合理的阅读限宽、渐进披露与内容顺序按有效设计核对；重复成本是否构成显著困难，结合该任务的实际使用频次与操作路径判断。证据不足时标明未核实，不靠布局阈值或推测用户会求助来升级。
