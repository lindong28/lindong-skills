# Web UI 维度记分卡

`design-ui`（正向）与 `review-ui`（反馈）共享的**同一套维度与判定契约**，`manage-ui-templates` 按产品类调整它。三方唯一的维度 owner——别在任一 skill 里另存一份维度表，改述会漂移。

**与 `${WEB_UI_SKILL_DIR}/references/web-ui-observation.md` 的分工**：那份管**怎么观察**；本档管**评哪些维度、目标从哪来、什么时候算达成**。要采集、比较或复核读数时按它办——它的「测量技术」「先画本次请求的网页观察覆盖图」「必须覆盖的轴」「有参照产品时的对比纪律」四节各自是那一步的权威；只维护覆盖层或元数据时不必整份读。

**一句话不变量**：**方向没有失败态。**「把读者的答案放在解释之前」这类句子，搬一个折叠块就满足了，而同一次改动可能让那一维变差——两者在这句话面前读数相同。所以每一维都要落成**读数 + 目标 + 判定**，目标缺就明写缺。

**模板任务**默认使用 [apply-ui-template](apply-ui-template.md) 的轻量验收，不因应用模板而强制建卡。确需本卡时，所选模板当前定义的规则与项目明确覆盖可以直接提供目标；参照侧未参与比较记 `无参照位（模板规范验收）`，不算缺证据，也不要求寻找商业站。模板示例提供实际读数时记录其内容摘要与身份。来源产品的历史截图和模板定义各说明自己覆盖的对象。

## 维度

### 全局层——每一维都要交代，本层不携带任何取向

| 维度 | 它问什么 | 读数从哪来 |
|---|---|---|
| 产品身份可辨 | 一眼看得出这页是干什么的、属于哪个领域，不是通用 AI dashboard 的长相 | `review-ui` 的视觉套用检查，结合产品任务与有效设计；**无数值读数**，是判断 |
| 读者要的东西优先 | 读者为这次访问而来的那样东西，排在解释与次要控件之前 | `${WEB_UI_SKILL_DIR}/references/web-ui-observation.md`「测量技术」表的「答案元素离读者多远」一行；`${WEB_UI_SKILL_DIR}/scripts/first-screen-density` |
| 信息架构与认知负荷 | 到主任务的路径有多长、每个决策点摆了多少个选项、方法与次要细节在答案之前还是之后 | `review-ui/cognitive-load.md` 的任务观察；选项数量仅作描述，不作为通用失败阈值 |
| 情绪历程与参与感 | 这一页给读者什么感受、那是不是它该给的、峰值与结尾的时刻设计过没有 | **无数值读数**，是判断。**取什么向由产品类定**，本层只要求答「它现在是什么感受、那对这个读者对不对」 |
| 可发现性与可操作性 | 下一步动作、当前交互状态，不靠说明文字就看得出来 | 交互状态实测（悬停 / 焦点 / 展开标记）；`design-ui`「Anything that expands must show that it expands, and its current state」 |
| 构图与响应式 | 必须并排比较的对象在视口允许时同屏共存；堆叠后仍能快速判断和扫描；用户缩放能在内容可见大小与密度之间取舍 | `${WEB_UI_SKILL_DIR}/references/web-ui-observation.md`「测量技术」表的「并排对比的两个块级对象共不共顶边」「一个区域里有多少在承载内容」两行，以及「必须覆盖的轴」的缩放目标与判定 |
| 字体承担信息职责 | 字号 / 字重 / 对齐 / 数字面让读者知道先读什么、哪些能对齐着比 | `design-ui` L2 的 type ramp 与 numerals |
| 文案无歧义 | 标签与按钮说清点下去会发生什么 | 抄下主动作的**原文**，写出读者据它预测的结果；预测对不上实际行为、或对得上多个结果，即为失败。重复交给 `${WEB_UI_SKILL_DIR}/scripts/page-repetition` |
| 色彩 / 主题系统自洽 | 存在既有自洽系统时默认延续，除非用户要求替换；不存在时按 `design-ui` L2 的 color roles 定一套 | 主题三态实测；`design-ui` L2 |

**本层只要求「别漏掉这一维」，不规定往哪边走。** 往哪边走由所选模板、参照物、产品契约或用户定；这些来源都没有时该维 `target-source: 无`，只报读数、不出判定。

**每一维先给适用性**：`适用` / `不适用（写理由）`。审一个孤立组件时，产品级身份与主题系统通常不适用；新建页面上「延续既有系统」没有对象。**`不适用` 是一种交代，不是漏项**——它要写理由，与「这一维适用、但读数没拿到」（下面 `未取得`）是两件事。

授权来源：用户 2026-08-27 原话「以后在设计和评价一个网页的时候，需要显式考虑到…8 个维度」。见上述 ADR。

### 硬约束——不是偏好，不可交易

产品正确性 · 可访问性 · 评测完整性 · 既有硬契约。任何维度的取舍都不得拿它们交换。

### Scope 覆盖层——由 `manage-ui-templates` 拥有

覆盖层能做三件事：给全局维度**定取向**、**加维度**、**绑参照对象**。它不能删除全局层任何一维，也不能放宽硬约束。

**本档只定义它能改什么。** 具体记录（当前批准了哪些、各自的取向与边界、批准 scope 与证据）由 模板仓 `library/webui/references/catalog.md` 的「Scope 覆盖层」节单一维护——**这里不复制一份，两处维护同一批取向必然漂移**。创建与发布路径见模板仓 `library/webui/references/admission.md` 的「Scope 覆盖层」节；本地／线上解析由 `manage-ui-templates` 提供。

## 记分卡

每维**七个正交字段**（下表逐行即全集——加字段时连这个数一起改，它是会独立漂移的量）。混用它们是本契约要防的头号错误——「有读数但不该设目标」与「该设目标但没测」是完全不同的两件事。

**`verdict-rule` 是最容易漏的那个**：有读数、有目标值，`达成` 仍然可以是无定义的——「1.2 屏 vs 参照的首屏内」到底算不算达成，取决于比较方向与容差，而那两样不写下来就只活在填卡人当时的脑子里。

| 字段 | 取值 | 各值含义 |
|---|---|---|
| `applicability` | `适用` / `不适用` | `不适用` 须写理由；其余字段留空。它答「这一维在本次对象上有没有对象」，不答「测没测到」 |
| `measurement` | **成对**（见下），每侧 `读数` / `未取得`；reference 侧另有 `无参照位`。三者的含义与影响见本表下方「reference 侧的三态」 | `未取得` = 这一侧没有一条完整、可复核的读数——数值缺、或数值在而采集身份缺项，都算；注记写明缺的是哪一样 |
| `target-mode` | `absolute` / `comparison-only` | `absolute` = 有具体目标值可判达成；`comparison-only` = 只并排 + 逐项作答，**不设目标、不出判定**（ADR-028 的形态，见下） |
| `target-source` | `所选模板` / `本次对齐目标` / `产品契约` / `用户明说` / `无` | 只放**来源**。`所选模板` = 所选当前定义中的适用规则，附定义位置及项目覆盖；`本次对齐目标` = 本次选定比较对象在该维的实测值，作用域只在本次任务；`无` = 这些来源均未规定目标 |
| `target-value` | 具体值 / `未取得` / `不可比` / `n/a` | `未取得` = **来源合法、但目标侧那条读数这次没采到**；`不可比` = 两侧条件不一致，须写出**是哪一项、两侧各是什么值**；`n/a` = `comparison-only` 或 `target-source: 无` |
| `verdict-rule` | 比较方向或 predicate + 容差 + 容差来源 / `n/a` | **`target-mode: absolute` 时必填**：写清「达成」是什么，并注明适用的容差及来源（所选模板、既有仪器契约、产品契约或用户明说）；定性规则用可观察的条件，不强造数值。要求精确相等时写 `exact，无容差`。`comparison-only` 记 `n/a` |
| `verdict` | `达成` / `未达成` / `不判定` | `target-value` 非具体值时**只能**是 `不判定` |

三条硬规则：

- **`target-value` 只反映目标侧。** 我方读数缺失**不影响它**，只令 `verdict = 不判定`。
- **`不判定` 不指示原因。** 它至少有四个来源：`comparison-only`、目标无合法来源、任一侧读数缺失、条件不可比。消费者**不得从这个 label 单独推断原因**——`comparison-only` 的空目标是合法模式而不是 finding。报 consequence 时按 `target-mode` + 缺失侧分别说；只有**本该有目标而缺**时才称为目标缺口。
- **`target-source` 只放来源。** `comparison-only` 是模式、`无` 是状态，各有各的字段。

### `measurement`：目标页面必测，实际比较时两侧各自完整

```
ours:      读数 · 采集时刻 · 视口 · 缩放档 · 主题 · 冷/热 · 交互状态 · 版本身份 · 取数命令
reference: 读数 · 采集时刻 · 视口 · 缩放档 · 主题 · 冷/热 · 交互状态 · 参照 URL · structure-origin · 取数命令
```

实际采集的任一侧缺项，该侧记 `未取得`，注记写明缺哪一项。模板规范验收不采集参照侧；规则本身不是页面测量，目标值从所选定义取得。

`measurement` 同时引用所用仪器的已有校准或对照证据，按 [宿主与执行约定](portable-runtime.md) 判断它能否区分相反结局；采集身份不替代刻度验证。证据有效则复用，仪器或被测路径变化只补失效部分。尚无适用对照时保留原始读数并注明未核实，`verdict` 记为 `不判定`；不新增记分卡字段或独立标定流程。

### reference 侧的三态

| 状态 | 什么时候用 | 它答的是 | 对目标字段的影响 |
|---|---|---|---|
| `读数` | 该对象有参照位资格，且这一侧读数完整 | 有资格 + 已测 | 可作 `target-source: 本次对齐目标` |
| `未取得` | 该对象**有**参照位资格，但这一侧读数缺、或采集身份缺项 | 有资格 + 漏测 | 无目标值可用，`verdict` 落 `不判定` |
| `无参照位` | 本次依据模板规范验收，或没有选定可实际比较的页面 | 本次没有需要测量的参照侧 | 不影响 `所选模板`、`产品契约` 或 `用户明说` 提供目标及判定 |

三态区分本次无需参照侧、已取得读数、应测而未取得；是否主动做过其他比较及其结果由 findings 承载。模板规范验收的合法缺席与原站对齐的漏测不会共用 `未取得`。

**填 `无参照位` 说明依据**：模板规范验收附模板内容摘要与定义位置；需要真实比较对象的任务附「先确定有没有参照」要求的观察记录。已选对象但未采到读数仍记 `未取得`。

**但要知道这些条件里哪些是仪器设得动的。** 冻结的 `--help` 实测（2026-08-28，base `244d6cc`）：

| 仪器 | 接口能固定的 | 接口固定不了的 |
|---|---|---|
| `visual-budget` | `--viewport` · `--settle-ms` | 缩放档 · 主题 · 冷/热 · 交互状态 |
| `first-screen-density` | `--viewport` · `--scroller` 等 | 同上 |
| `interaction-latency` | `--viewport` · `--click` · `--target` · `--timeout` | 缩放档 · 主题 |
| `page-repetition` | — | **连 viewport 都不收** |
| `page-acceptance` | — | **连 viewport 都不收** |
| `eval-identity` | 只消费 spec JSON | 不控制页面采集环境 |

**接口固定不了的条件，不得宣称「已在该条件下复现」**——记下它当时是什么，但那是环境状态而非受控变量；要判两侧同条件时，该维落 `未取得` 或 `不可比`，别假装它受控。要真控住，得由 `agent-browser` 这类能设置并回读这些条件的执行层承担，而本档不规定那一层。

**版本身份由填卡人核实**：记录实际对象和采集入口的内容摘要、URL、状态与时刻；对象摘要一致不证明读数来自该版本。按 [证据](portable-runtime.md#证据) 核对来源。

`structure-origin` 由模板仓记录来源，不限制已选模板作为设计依据。测量时写明实际对象是模板示例、目标产品还是商业原站。

**采集身份不是格式要求，它是让两种情况不再同形**：抄上一轮的读数会留下早于本轮实现的时刻与对不上的视口；凭实现自评则填不出一条真跑过的命令。

### `comparison-only`：ADR-028 治下的读数

L1 视觉用量（色相桶数、饱和色数、描边样式与密度、区域填充率、宽度认领）默认 `comparison-only`。`extreme-outlier` 仍按 ADR-028 定义单独报，它宣称的只是「相对该参照极端」。

理由不是保守，是校准结果：9 个公认高水准页面把几乎所有跨页判据逐条证伪（见 `design-ui`「为什么要分层，以及 L1 为什么几乎不做判断」）。**你若正要写「≤N 就是好」，就是在重复那次错误。**

`comparison-only` 的读数若取自 **<1440 桌面宽度**，保留原始读数但**不得**标为 ADR-028 覆盖下的 comparison/outlier 结论，在该维的注记里写 `出 028 作用域`。

## 参照位

以本次选定的实际比较对象为准，判据见 [web-ui-observation](web-ui-observation.md)「先确定有没有参照」。模板可以独立提供设计规范，其示例也可提供本模板的视觉与交互读数。商业原站对齐仍需原站同条件观察；记录、截图和测量结论说明实际来源与版本即可，不按是否派生排除模板。

## 控制骨架

本契约唯一的流程表。**跨文件引用请用阶段 label，不要用序号**——插一行就会让所有序号引用静默改指。

| 阶段 label | 谁 | 输入 | 动作 |
|---|---|---|---|
| `overlay-resolve` | `manage-ui-templates` | 产品类 | 解析本次生效的 scope 覆盖层（取向 / 加的维度 / 绑定的参照对象）。**这一步由本库执行**；调用方只负责在没有 critique 前置时主动问它 |
| `card-fill` | `review-ui`，或 `design-ui`（无前置 critique 时） | 覆盖层 + 渲染页面 | 建卡、填第一遍。参照侧按上面「reference 侧的三态」填，**不要为了填满而降级参照** |
| `implement` | `design-ui` | 同一张卡 | 消费它作为验收项。**不新建第二张卡** |
| `refill` | `design-ui` | 同一张卡 | 交付前用**同条件、同仪器、同参照**重填一遍 |
| `deliver` | `design-ui` | 重填后的卡 | 交付并报出全卡，含每一维的 `未取得` / `不判定` 及其原因 |

**`card-fill` 有两个入口**：`review-ui` 的产物就是这张卡；但正向任务（用户直接说「按 X 重构这一页」、没有先跑 critique）由 `design-ui` 自己建第一张卡——**没有 critique 不等于不填卡**。

两次填卡之间**不得换参照物、换视口、换缩放档、换仪器**；换了就是两张不可比的卡。**闭环的最后一条边（`refill`）归 `design-ui`**——不要在 critique 结尾邀请用户自己重跑。

## 对齐任务

**判据**：用户要求对齐真实产品的实际界面。此时 `card-fill` 与 `refill` 都是**必做**的，其余任务记分卡可选。指定模板并按其定义优化是模板应用，不因此触发商业原站对齐；真实阅读与交互仍按 [web-ui-observation](web-ui-observation.md)「交付前的最低证据」执行。

**多出来的义务只有一条**：`refill` 时参照侧必须**在本轮重新测一次**。参照侧读数早于本轮实现、或视口 / 缩放档与我方那次对不上时，该维 `target-value: 不可比`，写出两侧各是什么值。

## 本档拦不住什么

写在这里是因为不写出来，读者会把它当成一道闸：

- **`refill` 是自查，没有独立验证者。** 曾设计过一层「把成对证据交 `review-changes` 复核」的强制层，2026-08-28 的评审在**四个独立面**上判它不成立——`已验证` 是证据等级而非调度开关；`review-changes` 的 oracle provenance 查的是「谁在当判定 oracle」而非「被测页面是不是那个 live 产品」；纯 critique 轮它没有把记分卡当 review 对象的契约；以及上面那张表里 canonical 仪器根本控制不了要复现的采集条件。用户裁决砍掉该层。**所以填卡人自己就是唯一的读者。**
- **填卡人伪造读数、或抄上一轮的读数**——采集身份让「诚实填写下的条件不一致」可见，让「真实执行」与「形式化填写」**不可分**。
- **发现上界**：无。没有任何节点负责看那张卡。
- **仪器对照证据仍由执行者核验。** 上文 `measurement` 已要求引用适用的对照；字段填满和文件关联本身不能证明对照真实或仪器有效。缺少适用证据时按上文保留读数并不判定，不另建验证层。
- **「这个元素该不该在这一页」不由本档的任何一维产出。** 全局层 9 维里没有一维**产出得了**「移除 / 保留」这条裁决——「产品身份可辨」路由到的视觉套用检查、「信息架构与认知负荷」的可见选项计数都会报出存在侧的读数，但它们止于一条 finding 或 `不判定`。逐个清点独有元素、每个都交一次裁决的入口在 `${WEB_UI_SKILL_DIR}/references/web-ui-observation.md`「独有元素交用户裁决」，触发条件、射程与实测读数都归那一节。

关闭以上任何一条都要建一层能自己产读数、自己设采集条件的仪器；用户已两次裁决不建。公开包不依赖作者的私人评审记录。

## 扩展判据

修改维度或测量方法时，用本项目带真实反馈的正反案例检查新增判据是否可观察、能否区分相反结果。私人历史评测语料不随包分发；不能宣称已复跑作者的实验。
