# UI 规则归属与默认验收范围

本档是模板应用、设计与审核的范围入口。按用户选择的应用对象确定本次检查，不因打开一个网页而追加产品全审。

## 四层职责

| 层 | 拥有的内容 | 归属 |
| --- | --- | --- |
| 通用阅读原则 | 让读者理解信息含义、时点与适用范围 | [product-ux-workflows / 阅读原则](reading-principles.md) |
| 模板 | 风格提供视觉表达；场景提供任务结构、交互与显式阅读要求 | 当前模板定义 |
| 产品 | 状态事实、数据来源、业务口径、阈值与具体交互语义 | 目标产品实现与文档 |
| 通用 skill | 将适用规则映射到实际对象和状态，执行检查、关联证据和交代缺口 | 本主题的应用与批量核验流程 |

## 规则类别

| 类别 | 判定对象 | 归属 |
| --- | --- | --- |
| 视觉样式 | 字体、颜色角色、边框、圆角、图标笔画 | 风格模板 |
| 视觉组织 | 标签和值的分组、对齐、间距、密度、响应式及滚动后的关联 | 风格模板与目标布局适配 |
| 通用阅读 | 当前与历史、未知与真实零、单位和统计范围能否被理解 | 共享阅读原则 |
| 场景与业务语义 | 筛选影响哪些对象、过期阈值、历史配额能否触发告警 | 场景明确要求或产品 |

理解元素角色是视觉适配的前提，不等于重新定义业务。产品判定某值是历史快照；阅读原则约束它不被误读为当前；风格决定已有历史标签、时间与数值如何排列。标题在滚动中与所属值脱离是视觉关联问题；缺少历史身份或来源数据是阅读/产品问题。

## 应用对象与默认检查

| 应用对象 | 默认承担 | 交付边界 |
| --- | --- | --- |
| 仅视觉风格（style） | 适用视觉规则、视觉组织；保持既有内容含义与操作，本次修改造成的可读/可操作回归 | 不自动审计全产品的数据真实性、业务口径与通用阅读；已有语义问题另列 |
| 场景模板（scenario，可叠加风格） | 上述视觉检查，加场景显式要求的信息结构、交互、数据条件及适用阅读规则 | 对本次采用的场景负责，不扩成全部业务审计 |
| 明确 UX / 内容可理解性审核（ux） | 约定用户任务中的通用阅读、业务语义与真实操作；需要时同时检查视觉 | 按用户要求的范围给结论，不由风格模板定义业务正确性 |

普通 UI 改动按实际目标选以上范围；响应测量在用户要求、场景/项目既有契约要求、改动影响响应或已观察延迟时进行。风格应用仍真实操作受影响控件，不能把截图当作操作可用证据；出现实际延迟时沿性能诊断入口处理。

用户明确要求、项目已生效约束及当前模板的显式条款均须保留。旧项目检查和历史报告不自动成为当前模板；更新时按实际内容核对规则归属，保留历史证据原身份，不把移出风格范围的业务问题算作已修复。模板库只维护当前定义，不继续发布旧的混合版本。

发现问题时区分适用规则未落实、本次改动引入的回归、模板定义缺口、范围外的基线产品问题。前两者在本次授权内修复；基线语义问题单列来源和去向，不冒称风格违规，也不自动阻断风格交付。安全、授权、项目硬约束继续按其原有边界处理。

## 如何收敛

模板条款拆成可独立判定、来源明确的规则，按角色绑定所有实际组件变体及有关状态。脚本批量查确定性属性、数量、几何和已观察失败；agent 判断视觉组合，阅读/业务判断只在上表范围内执行。选择器匹配不证明规则映射完整，须从真实页面反查遗漏对象。

整站或多页任务固定一份完整有效设计与项目清单；后续增量复验引用它，不另建缩小分母的独立清单。完整范围与本次已执行子集分别报告，未运行、未观察和不适用分开。操作契约见 [批量核验](batch-ui-verification.md)。这使遗漏可见，不保证一次消灭所有未来缺陷。
