# 探针校准历史

以下为原 web-ui-design「为什么要分层，以及 L1 为什么几乎不做判断」正文的保留记录；历史读数未在本次整理中重跑，当前执行入口见 [design-ui.md](../design-ui.md)。

*（本节是校准记录。在你想加一条阈值之前先读它。）*

有一个页面交付时 L2 做得**完全正确**——闭合的 spacing ladder、带嵌套规则的 radius family、为 CJK 选过的逐档 line-height、刻意设置的 `--measure`——在 L2 validator 上拿到 **10/12「system present」**，却被它的 owner 判为杂乱、难看、浪费空间。同一次运行、同一个 viewport，他满意的那个参照拿到 11/12。另一个他**同样**满意的页面拿到 **0.417，并被记成「没有系统，不要再选它当参照」**。

L2 validator 的读数**在那个样本上与满意度反相关**，而在它确实跑到的那些检查上，被嫌弃的那个页面反而赢了（motion 覆盖率 100% vs 79%；tabular numerals 65/65 vs 2/2）。它不是沉默，它指错了方向。owner 反对的每一件事都住在 L2 之上：构图、开销、form factor。

于是 L1 被建了出来。然后拿 9 个广受认可的页面去校准它，而**这次校准几乎把它整个杀掉了**：

| 候选判据 | 裁决 | 反例 |
|---|---|---|
| 色相桶少 = 好 | **证伪** | IBM Carbon 8、AWS Cloudscape 9——两者都高于被判为差的那个页面（6） |
| 饱和色少 = 好 | **证伪** | Cloudscape 100 |
| 边框样式少 = 好 | **证伪** | Plotly 15 = 那个差页面的 15 |
| 边框密度低 = 好 | **证伪** | owner 最喜欢的那个参照在 21.8；差页面在 25.6 |
| 区域填充率 | **证伪** | 它那 54% 来自一个*正确*的 `--measure`；毛病出在容器宽度，不在 measure |
| 宽度主张 | **三种操作化全部失败** | `<main>` 盒 → 5/5 退化到 1.000；整页 ink 并集 → 差页面读到 0.975（一条通栏 banner 就把它填满了）；穿过数据区的扫描线 → 差页面的 0.703 *落在*两个受欢迎页面的 0.677 与 0.762 *之间* |
| 重复 badge 计数 | **只以「极端离群」的形态存活** | 好页面 0–48，差页面 1767。**48 与 1767 之间没有任何采样**，所以不存在边界 |

**最后一行有一条 caveat，而且正是那种会悄悄让一次校准失效的**：那些语料数字是用一条更早的计数规则取的，它要求 badge 必须是一个没有子节点的叶子。一次外部 review 表明那条规则依赖 DOM 结构——把 `<span class=badge>OK</span>` 再套进另一个 span，计数就从 1 变成 0，而像素一个都没变——于是该规则被换成了绘制与几何检测加嵌套去重。两个锚点在新规则下重新量过，两个裁决都仍然成立（差页面 1754 vs 14 = 125×，触发；修好后的页面 3 vs 14，不触发）。**另外九个页面没有重测**，所以把 0–48 这个区间当作旧规则下的指示性数字，而不是当前规则的一条已校准的带。

**区域填充率作为回归检查比没用更糟——一次好的改动会让它朝反方向动。**实测：一份交付报告把过大的摘要块修好之后，`data_region_coverage` 读到 **0.672 → 0.37**，*而 `scan_y` 完全相同*（1078）。用 `visual-budget <url> --ready 'section>=5' --data-region main --json | jq '.page.scan_y, .page.data_region_coverage'` 对着 `video-eval-arena` 的 `arena/static/rt-delivery-report.html` 在 commit `889c870` 前后各跑一次即可重新推导出来——这个读数是那一对页面的性质、不是本文件的性质，所以它是可复现的而不是被断言的。没有任何东西变窄；是上面那个块变短了，于是那条唯一的扫描线不再落在一张有绘制背景的卡片里，转而落到了按它正确的 74ch measure 排的散文上。这里有两种失败形态，危险的是第二种：这个指标是区域中心的**单独一条线**，所以它报的是恰好落在某一个 y 上的东西；而且因为「已绘制」包含容器背景，**一个页面的卡片外观越多，它读起来就越密**。不要拿它做前后 diff——一旦做了，它会告诉你那次改进是一次回归。

**教训是这一节本身，不是那张表**：跨页面的视觉开销阈值，没能在一个多样化的语料面前存活下来。两个数量级是看得见的；两倍不是缺陷。如果你发现自己正要写「≤ N 就是好」，那你正在重复本文件被重写下来所要记录的那个错误。
