# 按模板优化 Web UI

所选模板的当前定义与项目明确覆盖共同构成本次设计和审核依据。模板的商业来源用于溯源；日常应用无需访问该网站。针对模板缺口的来源研究走 [review-ui](review-ui.md#组件巡查与来源研究)；用户要求更广泛研究或对齐商业原站时，另走 [adapt-reference-ui](adapt-reference-ui.md) 或 [design-ui](design-ui.md) 的参照分支。

## 定义与目标

先按 [UI 规则归属与默认验收范围](ui-rule-ownership.md) 明确本次应用的是风格、场景还是 UX 审核；应用与审核共用该范围。

按 [manage-ui-templates](manage-ui-templates.md) 取得当前实际定义；用户已指定模板就直接采用。核对目标仓、页面和读者任务，从定义中读取主题、布局、组件、适用范围，以及存在时的 `design_profile` 和 `acceptance`。当前 API 内嵌的设计基线与定义一并读取；本次实现与审核使用同一份实际输入。以当前定义实际声明的字段为准，明确未规定的部分，不用旧定义补齐当前标准。

按 [manage-ui-templates 的有效设计规则](manage-ui-templates.md#本次有效设计) 合并场景、显式选择的风格与项目覆盖，并核对模板的数据条件。将规则落实到目标真实内容：风格应用核对视觉层级、分组和不同状态的呈现；场景应用还落实其声明的任务顺序、常显操作和详情入口。多页应用复用同一有效设计，在目标项目现有组件和样式层落地，不给每页重新选字号、间距与控件样式。

明确要求和项目硬约束优先；记录本次确需的项目覆盖及理由。保留品牌、权限和业务语义，允许改善本次优化范围内的排版、密度和信息组织；“沿用项目主题”不冻结现有缺陷。模板未规定的地方沿项目可用规则设计，不因缺少商业参照暂停。业务功能取舍仍按已有授权处理。

场景包含子页面与模块时，按 [整套、子页面与模块](manage-ui-templates.md#整套子页面与模块) 固定采用范围。仅将所选子项及适用公共衔接规则映射到目标；整套模板的存在不授权新增全部页面或能力。只选模块可对接已有承载区域，核验该入口及本次影响的上下文即可。

## 整站与多页范围

目标为整个产品时，结合路由、导航及实际使用入口列出页面与详情状态清单，包含查询参数驱动的视图；主页面 URL 不代表整个范围。按 [组件与状态覆盖](manage-ui-templates.md#组件与状态覆盖) 建立规则对应，读取当前定义关联示例。定位共享样式与组件入口，先落实共同视觉，再处理页面差异。风格定义中的主题规则和 tokens 同样适用于没有场景模板的页面。

在同一项目记录中逐项列出应用状态、例外与验证入口；已通过共享样式继承的页面仍需实际观察。按不同页面结构验证字号、控件、表面层级及宽窄屏，并沿导航进入详情检查连续性。未检查的页面明确标出，不以三张截图或共用 CSS 文件推断全站完成。保留项目共同设计作为后续新增页面的入口，不复制每页一套规范。

多页或重复组件规则使用 [批量核验](batch-ui-verification.md)：固定规则、项目绑定和通用执行器分层；人工核对规则编译完整性，程序保留每个声明页面状态的检查结果与未核实项。共享改动按受影响消费者选择复验，不能把抽样或旧结果外推为全站通过。

适用的父级旅程和子项跨页要求按 [单页状态与跨页旅程](batch-ui-verification.md#单页状态与跨页旅程) 另取实际操作证据，与页面状态结果并列交付。

保持可追溯链路：**规则来源 → 适用对象/状态 → 核验方法 → 证据 → 结论/处置**。模板拥有通用设计规则，应用流程负责完整映射，目标项目拥有绑定及业务语义，通用执行器负责结果关联。将可独立判定的规则分别编译，不把一整章压成一个 manual 后以单张截图判通过。视觉组合按共享观察入口检查；阅读与业务判断按本次应用范围纳入。范围外的基线产品问题单列，不追加成本轮风格规则；本次造成的意义回归仍须修复。

## 实施与验证

向 [design-ui](design-ui.md#template-library-交接) 交付模板身份、有效规则、项目覆盖、目标路径和观察范围，完成实现。示例用于理解模板的布局与交互；实际验收在目标产品中进行，使用真实内容及本次自然出现的状态，按 [web-ui-observation](web-ui-observation.md) 在既定范围内观察视觉关系、实际操作及本次适用的阅读/响应项。

应用和审核消费同一份有效设计；检查既有实现是否满足任务，已有符合项保留，不为证明应用过程而制造改动。按组件核对实际渲染与操作结果，明确规格可用定向检查，信息层级和复合状态仍须实际阅读。共享实现变化时检查其受影响的其他消费者。会触发业务写入的状态可在隔离样本中检查外观，并与真实业务结果分开报告。结论分开交代：

| 结论 | 所需证据 |
| --- | --- |
| 操作与内容保持／场景功能 | 风格检查受影响操作与原有含义是否保持；场景再核显式要求的操作结果与业务口径 |
| 模板符合 | 对适用规则及 `acceptance` 逐项给出结果、项目调整或未核实项 |
| 视觉效果与适用阅读项 | 实际页面的视觉主次、关联、跨页一致性和交互状态；按范围纳入的阅读规则单列，未查业务不宣称正确 |

沿用本次任务记录即可，不为应用模板新建大型记分卡。用户要求完整设计评审或项目已有要求时再用 [review-ui](review-ui.md)；仅审核则止于证据、问题与建议。缺少商业原站读数不构成模板任务的失败或漏测。

使用批量执行器时，按 [阅读结论闭合](batch-ui-verification.md#阅读结论闭合) 将实际阅读写回对应页面状态和规则，保留原机器报告。修复后重跑受影响检查并重新观察；证据绑定实际输入字节与运行，旧阅读票不能迁移为更新后内容的通过结论。尚未阅读的条目、功能结果和模板编译完整性仍分别说明，不用聚合报告代替这些判断。

## 交付

报告模板 ID／内容摘要／实际来源、已实施范围、有效项目覆盖、上述三类结果与未完成项；提交、发布、部署按实际状态分别说明。按 `manage-ui-templates` 将应用结果和用户反馈写回目标项目的同一份记录；可复用缺口按 [维护的授权边界](manage-ui-templates.md#维护) 处理，项目特殊行为留在目标仓。已有巡查发现沿 [修复反馈与收敛](review-ui.md#修复反馈与收敛) 用原失败条件关闭，不以规则新增代替修复。
