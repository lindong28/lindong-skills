# 用 Codex 内置 image_gen 出图（与站点样例同源的那条路）

站点模板页上的多模态样例图就是这样生成的。模板 API 的 `sample_generator` 给出该模板样例实际用的通道与执行配置（当前全部模板为 `{"channel": "codex builtin image_gen", "model": "gpt-5.6-luna", "effort": "high"}`）；**以 API 的读数为准**，本文件不复制一份会漂的值。

## 前提

- Codex CLI 已登录 ChatGPT 订阅账号；内置 imagegen skill 位于 `$CODEX_HOME/skills/.system/imagegen/`（`CODEX_HOME` 未设置时为 `~/.codex`，由 Codex 自动安装）。
- 执行 agent 的 model 与 reasoning effort 取 API `sample_generator` 的值。**只有启动时显式已知或可见的 session 配置才算合规证据**；取不到这份读数就按不合规处理，不由当前 session 自行推定。

## 怎么调

已在符合配置的 Codex 会话里：直接用内置 imagegen skill，把 `prompt.txt` 全文作为图片任务原文交给它，附参考图时一并传入并说明它是风格参照。

配置不符或需要独立会话：派发一个**显式指定** model 与 effort 的 Codex 会话再出图，不切换当前主会话。宿主自带的具名出图入口（如果有）优先于裸 `codex exec`——具名入口用于防误派。

要交给它的内容只有三样：`prompt.txt` 全文（原样，不改写、不做 specificity normalization）、参考图路径及其角色标签、最终保存路径。执行参数不是画面内容，不写进绘图文本。

完成后从它的输出里取三样：最终 PNG 的绝对路径、实际使用的最终 prompt、**用的是内置 `image_gen` 还是 CLI fallback**。

## 失败处置：逐行判，命中即停

**任何失败都不得自行改用别的模型、API key 或 CLI fallback 生成替代结果。** 那会让产物与站点样例不同源，而交付物上看不出区别。

| 失败类别 | 处置 |
|---|---|
| **这条路走不通**——配置取不到或不满足、内置工具不可用、未登录 | 停止并如实报告。这一类没有重试：重试的是同一个不合规前提。未登录时让用户先 `codex login` |
| **重发也不会有实质不同结果**——输入被拒（如 `moderation_blocked`）、配额或额度耗尽 | 不重试。前者同一 prompt 必然同样被拒，要的是改输入或换候选；后者报出 reset 时刻与它属于哪个 limit，取不到就写「响应未含 reset」 |
| **其余的调用失败**——这一次 `image_gen` 工具调用超时、断流、5xx、带明确 reset 的速率限制 | **先确认这次调用是否已经产出可回读的产物**（`$CODEX_HOME/generated_images/` 下的新文件）：**有就接住它、不重试**——服务端已生成即已计费，重试是再付一次；没有才在同一条合规路径上重试，默认最多 2 次、指数退避（速率限制则等到 reset 之后）。用尽仍失败则跳过这一件资产、其余继续，并在报告里记为已跳过 |

第 2、3 行的分界是「同一请求原样重发，稍后成功的机会有没有实质变化」，不是那几个词本身；新出现的限流或拒绝形态按这条判据归行，不对着词表匹配。**判不出属于哪一类时落「不重试」并如实报告**——付费不可回收，默认取保守侧。

报告里写明报了 CLI fallback 还是内置 `image_gen`：**报 fallback 就是没用上订阅额度**，立刻告知用户并停止，不默认重试——先排查认证状态。

## 多张一起出

并发单位是「多个各自带全套身份参数的调用」：把上面「怎么调」重复 N 次，每次都带齐 model 与 effort。不要用只能批量派发、却携带不了这两个参数的入口——那样建立不起合规证据，批次会静默跑在别的配置上，而产物已计费、不可回收。

并发度由订阅配额池的容量定（配额速率、单账号在飞上限），N 个调用争用的是同一个池，不套通用的「默认 8」。

## 边界

本文件约束的是调用方采用的显式执行配置与 fail-closed 行为，不构成对后端运行时身份的审计，也不保证生成服务成功。用户明确要求走别的 API 或 CLI 时属于独立路径，可以按其明确选择执行，但**不得声称与站点样例同源**。
