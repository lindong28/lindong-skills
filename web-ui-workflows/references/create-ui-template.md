# 从参照网站创建 Web UI 模板

将真实参照中可复用的设计沉淀为模板，使后续 session 仅凭模板就能应用和审核，不必重新访问来源网站。视觉风格和场景模板都可独立创建；目标产品与第二产品验证是可选输入，不是入库前置条件。

## 输入与职责

从请求取得参照网站及观察范围、希望提炼的风格或场景、模板仓位置（由用户提供实际路径与访问权限）和已授权产出。复用上下文，只补问会改变结果的缺失信息；来源账号和访问方式留在任务记录，不写入通用 skill 或公开模板。用户只要求研究时交付分析，不自动写入模板。

只应用已有模板走 [apply-ui-template](apply-ui-template.md)；参照网站改造指定产品走 [adapt-reference-ui](adapt-reference-ui.md)，由它按需回传提炼任务。读取、分类、规则合并和入库维护的权威为 [manage-ui-templates](manage-ui-templates.md)；本流程不另建 catalog、模板副本或发布机制。

## 创建或更新

| 环节 | 产出与边界 |
| --- | --- |
| 查现有模板 | 读取模板仓规则与 `library/webui/references/admission.md`，按 manage 的入口查询当前定义。先判断复用、更新或新增：已有模板能承载的直接完善当前条目；新增须有独立复用价值，风格与场景均适用。 |
| 观察真实参照 | 先按用户选择参照的理由定位具体页面或状态，再使用 `agent-browser` 和 [web-ui-observation](web-ui-observation.md) 确认其中实际呈现了要借鉴的内容，观察代表组件和安全可展开状态；未取得匹配页面时报告缺口，不以同一产品的其他页面替代本次参照。记录具体入口、与选择理由对应的观察证据及未核实项；来自 adapt 或本任务的匹配证据可复用，缺口才补查。认证受阻按 [运行与依赖](portable-runtime.md) 的认证边界处理，替代材料与推断不得称为真实操作。 |
| 提炼规则 | 按 [UI 规则归属](ui-rule-ownership.md) 区分视觉、场景、通用阅读原则和产品事实。风格描述可跨页的字体、颜色角色、间距、密度、表面和组件状态；场景描述读者任务、信息结构、组件关系、交互及适用的数据条件。产品特有业务留在产品，未观察到的设计扩展标明为提议。 |
| 完成模板 | 沿模板仓当前格式更新定义、必要的共享基线、代表性示例及应用／审核 Prompt。承重规则写入定义，示例展示组合和状态；按 [模板来源](manage-ui-templates.md#模板来源) 保存可复用入口和观察边界，说明适用范围及限制，让模板消费者无需原站或私有观察记录也能执行。应用与审核引用同一当前定义，不复制一套规则进 skill。 |
| 模板侧验证 | 按目标仓现有校验和构建入口检查定义、依赖资产、页面、API 与复制文本的一致性；以真实浏览器使用示例和复制入口，核对所声明规则的呈现及交互。覆盖范围按模板类型与实际声明确定，未覆盖部分明示；不以 build 成功替代视觉验证，也不以示例可用宣称产品应用成功。 |
| 入库与交付 | 回到 manage 的维护与目标仓发布流程，完成已授权的提交、入库及发布。具体内容尚待批准时先完成可审候选，再按目标仓规则取得裁决；已有适用授权不重复询问。源网站被认可不等于所有新内容已批准。 |

机器可测规则采用模板仓已有规范；项目定位器与状态操作留给应用项目，通用批量执行复用 [batch-ui-verification](batch-ui-verification.md)，不因创建模板而建立新的检查框架。尚无产品绑定时不宣称已经完成产品级批量核验。

用户同时授权产品应用时，向 `apply-ui-template` 交付当前模板身份、实际定义来源及目标范围；需要继续参照驱动的功能改造时回到 `adapt-reference-ui`。应用发现的通用缺口经 manage 更新当前模板，项目例外留在项目，不强制每次创建后改造一个产品。

创建或更新场景时，按 [维护的层级放置判据](manage-ui-templates.md#维护) 确定顶层场景、子页面或模块，交付相应父子归属；不因来源网站多了一个 URL 就新增顶层模板。

## 交付

交代模板 ID、类型与实际路径，复用／更新／新增的结果，真实观察与推断的边界，模板侧验证范围及未核实项，以及候选、入库、提交、线上发布的实际状态。用户未要求产品应用时明确本次止于模板；执行过应用时另报目标产品证据，用户认可也独立记录。沿用任务和模板仓既有记录，不新建平行账本。
