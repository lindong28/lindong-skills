# 单产品介绍与上手

用于新建或整体改进一个产品的宣传首页：让初次接触的读者理解价值、看到可信的具体结果，并知道怎样开始。局部文案或样式修正只检查受影响部分；已指定的品牌、风格和业务边界继续作为输入。本方法接入现有 design-ui 与 review-ui，不新增审批、固定候选数或评分流程。

## 从产品结果选择表达

从产品说明、实际能力和对话提炼主要读者的困扰、产品接受的输入、帮助完成的事情、可展示的结果及开始条件。它们应能支持一句具体的价值表达和一个主要行动；未知事实继续核实，素材不足时保留缺口。实现中的模块名、可靠性机制或功能清单不能独自承担宣传叙事。

为核心用途选择可辨认的场景：展示任务、界面、产物或前后变化，使读者看得出产品怎样帮助自己。用真实界面或结果时核权限与版本；合成场景明确标为示例。没有可信素材时可采用文字、原创图形或页面内演示，不虚构客户、评价、业务成功或实测数据。交互应帮助理解不同内容或状态；读完一个场景不必依赖反复点击“下一步”。

## 选择可用的依据

复用本项目已选设计，再查模板库和适用参照。单产品介绍与上手可查询场景 product-introduction；多产品发现与选择可查询 product-discovery-portal，按实际定义判断，不凭名字强套。读取当前完整定义、示例和适用条件；开发快照尚未公开时使用明确指定的同版来源，不能静默回退其他版本。

比较候选对本次内容的表达：首屏的视觉主体能否解释价值，文字与成果是否互相支持，整页的重点与节奏是否清楚，主要动作是否接到真实开始路径。说明借用、调整或不采用的理由；颜色、字体、卡片或某个来源品牌不自动证明适配。已有充分依据时直接使用，缺少关键层才研究，不把搜索数量当作设计质量，也不把一个产品的采用升级为长期默认。

## 在可调整时检查实际画面

先把最能决定方向的部分实现成可观察的页面，通常包括首屏和一个核心场景，作为最终实现的一部分。将实际渲染与产品目标及选定依据放在一起看，判断是否仍像可套到任意产品上的包装、重要内容是否被装饰或次要说明压过。发现方向问题时先改这个决定，再展开其余页面；不默认另建原型项目或要求用户批准每个细节。

按内容关系安排后续段落：能力、场景、适用边界和上手说明可以采用不同组织方式。卡片、编号、背景和动效表达真实分组、顺序或反馈；保持必要的一致性，同时让不同用途有可辨主次。主动作及其必要条件容易取得，详细运维和诊断信息按读者需要承载。首屏构图、场景与整页节奏分别判断，统一 token 不能代答。

## 回到读者结果验收

沿页面实际说明，从介绍进入场景和开始路径；依据页面可见内容解释“适合谁、能得到什么、如何开始”，再核对产品事实。分别给出用户任务、设计表达和实现正确性的结论。用实际宽窄屏、相关展开或切换状态检查层级和关系；与参照比较运行画面时使用可比视口、缩放和状态，未观察部分如实保留。

交付前对照采用的依据和产品内容，主动处理仍然抽象、重复包装、重点错位或场景不可信的部分。判断须指向具体画面、读者得到的答案和相关取舍，不能仅报截图、测试、按钮或 CSS 一致。用户需要选择的剩余审美取舍按宿主提问入口收回；agent 自己能检查和修正的先完成。设计自评、用户认可与真实使用效果分别报告，不声称单个模板保证最优审美或转化效果。
