脚本资源根目录（`baseDir` / `SKILL_DIR`）为 `${WEB_UI_SKILL_DIR}/workflows/design-ui/`，正文的 `scripts/` 路径以此为准；文档链接相对于当前文件，专属参考在 `design-ui/`。


提供一个网页界面所需要的东西，使它看起来是被设计出来的、而不是拼装出来的。这是创作侧；`review-ui` 是判断侧。

来自 [adapt-reference-ui](adapt-reference-ui.md) 的任务，复用其参照证据、目标任务、采用范围和业务约束完成本次设计与实现；验证后把实际结果和可复用部分交回该流程处理模板。单纯视觉对齐直接使用本流程，无需先做完整能力盘点。

来自 [apply-ui-template](apply-ui-template.md) 或用户指定模板的任务，以当前定义与项目明确覆盖为依据；先读本档「Template-library 交接」。模板路径不进入「拿到一个参照」的商业网站寻找流程，也不因来源站不可访问而暂停。

## 适用与进入时点

页面没有视觉系统或系统不自洽时，在写 CSS 前进入本流程定参数；新建界面、整体改版、参照产品复刻或被判“像拼装出来的”均按这个条件判断。改动体量不是判据，无系统页面上的一次小添加同样适用；观察与评判能指出问题，不能替代设计参数。

孤立的布局 / 样式 bug 按普通修复处理；已有设计系统内的改动沿既有系统走，不因此扩成整页重设计。但“已有系统”须按「这个页面已经有系统了吗？——逐层去问」取读数确认，不能默认成立，也不能用单条 FAIL 判为没有系统。系统判据、误报解释与未核实边界由该节维护。

引入或替换页面图片（含 CSS 背景）时，在实现过程中应用 [图片交付](optimize-images.md)。即便没有人报告过加载问题，它那道轻量检查也属于图片交付。

**控制流：**按任务决定是否使用维度记分卡 → 适用时查已批准的 evaluation shell → L0 form factor → L1 开销 → L2 参数。参数检查不能代替前面的形态与用量判断。

| 层 | 决定什么 | 仪器 |
|---|---|---|
| **L0 form factor** | 这是哪一类界面：workbench / document / feed / dashboard | 判断，或整体照抄一个参照 |
| **L1 开销** | 这个页面把每种视觉手段各用了多少——多少个 badge、多少种色相、占用多少宽度、页面有多长 | `${WEB_UI_SKILL_DIR}/scripts/visual-budget`；离群、差异筛选与包装去重使用下文说明的未校准参数 |
| **L2 参数** | token 取值：spacing ladder、type ramp、radius family、elevation、motion、state matrix、color roles | `scripts/validate-visual-system.js` |

## 维度记分卡——修 L0 之前先读它

维度集合、每个维度的字段 schema、target 可以合法地来自哪里，以及逐步流程，全都住在 **`${WEB_UI_SKILL_DIR}/references/web-ui-dimension-rubric.md`**。它是与 `review-ui` 和 `manage-ui-templates` 共享的单一拥有者——本 skill 不另留一份副本，因为改述会漂移。

**先按该档「对齐任务」判断适用性**：用户要求对齐真实产品的实际界面时，建卡与交付前重填必做；模板应用等其余任务记分卡可选。项目契约或本次要求已规定用卡时照其执行。无卡不免除真实阅读、交互及本工作流的 L0/L1/L2 验证。

使用记分卡时，本 skill 拥有 `implement`、`refill` 与 `deliver`：复用本次已有的卡，不新建第二张；没有卡才解析 `Scope 覆盖层` 并建卡。交付前按同条件、同仪器、同参照重填，报告全卡及未取得项。对齐任务的参照侧仍须本轮重新测量，旧读数不能代替；闭环由 agent 完成，不交用户重跑。

未使用记分卡时直接报告本次目标、实际观察、判据与缺口，不为凑表补建一张；观察要求仍归 `web-ui-observation.md`。

## 评测场景查找

做 pairwise 评测或评测排行榜这类活时，先向 `manage-ui-templates` 要`task-first-pairwise-evaluation` 或 `scan-first-evaluation-leaderboard` 场景模板，核对当前定义与批准范围。场景提供的是关系，不是目标产品的视觉语言，也不是修改被评测对象与观看条件的许可。

选定模板的定义与示例可作为该模板任务的设计依据；示例的身份与实际内容须明确。用户要求商业原站对齐时，才需要对应原站的实际证据，模板示例的读数只说明模板自身。

## Template-library 交接

按 [manage-ui-templates](manage-ui-templates.md#本次有效设计) 解析有效设计；复用已有记录，不重新选择风格或覆盖。按 [UI 规则归属](ui-rule-ownership.md) 保持调用方的 style / scenario / ux 范围；L0/L1/L2 是视觉检查粒度，不改变任务范围。所有模板使用同一份简短交接：模板 ID、内容摘要与实际来源；目标任务与 viewport；有效布局、组件、视觉规则及存在时的 `design_profile`／`acceptance`；项目与局部覆盖；适用范围和已知限制。没有匹配覆盖层就说明无覆盖层，不为交接补建记分卡或分类组合。

保留项目品牌与业务约束，按选定模板改善本次范围内的字体、间距、密度和信息层级；明确覆盖的规则与理由。跨页应用复用同一个设计基线。模板未规定的部分沿项目可用规则补齐，定义缺少字段时须说明其覆盖范围。

模板路径的 L0 由场景任务与布局决定，L1 依据模板的信息优先级和实际页面内容判断，L2 采用有效 token 与项目覆盖。无外部参照时不强制运行成对 `visual-budget`；可直接在目标页测量有关结构及视觉用量，按下文 L1b 解释其含义。选用模板示例做成对测量时，结论仅指与该模板示例的差异。交付按 `apply-ui-template` 分开说明功能正确、模板符合和视觉实测；完整记分卡仅在本次要求或项目契约需要时使用。

## 为什么要分层，以及 L1 为什么几乎不做判断

L2 参数检查不代表构图、视觉用量或读者满意度；L1 聚合读数也不能直接当作质量分数。相对离群及差异阈值仍按下文的适用域与限制解释，不能从未触发推出页面合格。

调整探针判据、解释历史校准读数，或准备将视觉用量当跨页标准 / 前后质量回归指标时，读取[探针校准历史](design-ui/probe-calibration-history.md)。其中保留样本、计数规则变更与单扫描线反例；不是每次设计都要重读的执行步骤。

## 同样的像素可以读成克制、也可以读成浪费——而其中只有一个是可测的

让这类活开始的那句抱怨通常是*「它没用上空间，两边就那么空着」*。这句抱怨有时是真缺陷，有时是一个正确的 `--measure` 在正常工作，**而截图分不出是哪一种**——两者看起来一模一样。这里实测过：一个报告页被人从截图上读成「散文左对齐在一个 1520px 的容器里，留下一片参差的空洞」，差点就按通栏改造去修了。实际读数是：散文中位数 **710px = 74.0 ch**，容器 **1560px**，表格 **1254–1288px**——也就是说，这个页面早就完全按 `reading-instance.md` 规定的方式实现了 document 档。根本没有东西要修。（来源页面：`video-eval-arena` 的 `/report`，即 `arena/pages/report.html`，在 1920×1080 下。重新推导的方法：取它 `p` 元素的 `getBoundingClientRect().width` 中位数，除以它们计算字体下一个 `0` 的宽度——这些数字是那个页面的性质，不是本文件能定下的主张。）

**在把「浪费的空间」当成缺陷之前，先取一个读数：文字是不是正处在它自己那一档所声明的 measure 上？**

| 读数 | 裁决 |
|---|---|
| 文字按声明的 measure 排（~65–75ch），而非文字内容——表格、卡片、代码——占满整列 | 不是缺陷。留白就是设计。把这句说出来，然后停手。 |
| 文字按声明的 measure 排，但**其它一切都被跟着一起限宽了**，于是表格和卡片挤在同一条窄带里 | 限宽加错了元素——它该加在文字上，不是加在容器上 |
| 文字排得明显**窄于**它声明的 measure | 上游有东西在吃掉这个 measure——先把它找出来，再谈加宽 |
| 没有声明 measure，而这一档**本来有**（document、feed，以及 workbench 里的散文区域） | 这一档的参数根本没被应用过。先去把它们拿到，再来评判留白 |
| 没有声明 measure，而这一档**本来就没有**——一个全是控件与数据的通栏 workbench、dashboard 或 canvas | 这根本不算一条 finding。按它自己那一档的轴去判它；缺 measure 说明不了 L0 有没有被决定过 |

**最后两行之所以存在，是因为把它们合并曾是本文件里的一个真实错误**（由外部 review 抓到）：「没有声明 measure」当时被写成了「L0 从未被决定」，这会把 agent 打发回去，在一个 form factor 早已定下、只是里面没有散文的页面上重做 form factor。*先*问它是哪一档；measure 这个问题只有在一个定义了 measure 的档次里才有答案。

这件事值得立一条规则的理由：第一行与第四行产生**相同的**视觉印象，而正确动作**相反**。把第一行加宽是破坏，而且是会被表扬的破坏，因为「现在它用满整个屏幕了」正是那句抱怨要的东西。

## L0 —— form factor，先于任何 token

先给这个界面命名，再给它做样式。下游的一切都从它继承，而且这是唯一一层照抄参照既便宜又正确的。

| Form factor | 读者来这里是为了…… | Shell |
|---|---|---|
| **workbench** | 在大量记录上操作，边比较边下钻 | 通栏 shell，常驻 nav 独占一列，主区域流式，数据出现在第一屏 |
| **document** | 从头读到尾 | 单列限宽，宽裕的外边距，锚点导航；见 [`design-ui/reading-instance.md`](design-ui/reading-instance.md) |
| **feed** | 扫一眼，找出值得点开的东西 | 重复的卡片，一列承载关注点，扫读成本低 |
| **dashboard** | 一眼看到状态 | 固定平铺，主要答案不需要滚动 |

**交互报告按读者任务选形态，不因名称含“报告”就套 `document`。** 多对象导航、关系图和宽表支撑比较与下钻时，默认用 `workbench`：外壳使用可用宽度，导航占稳定一列，主区随视口伸展；散文行长只在文字块内限制，不限住图表的共同祖先。仅从头读到尾的散文报告仍用 `document`。验收时实际阅读图表，确认新增空间确实到达内容区，而非只有页头或空容器变宽；窄屏继续重排。

**上面这四个不是一个封闭集合**——editor / canvas、chat、wizard / 表单以及 landing page，老实说都不属于其中任何一个。一个都不合适时，用你自己的话给这个界面命名并说明；硬塞进这四个里的某一个，比承认这张表覆盖不了它更糟。

**这里只有 `workbench` 与 `document` 有实测的前后证据**（一个页面，一次改造）。`feed` 只有一个旁证样本；`dashboard` 一个都没有。对这两个，产出读数并说明该 form factor 未经验证——不要从它们推导出判断。

**L0 从未被决定过的征兆**：这个页面为「形状不对」的各种症状被反复打补丁。像*「这个原来在入口下方 1.06 屏处」*、*「一个 33000px 的页面完全没有导航」*、*「这个块是展开的，占掉了到第一个视频那段距离的 42%」*这样的说法，每一条都是局部正确的修复，却永远不可能质疑形状本身，因为从来没有人把形状摆上桌面。

## L1 —— 开销，对着一个参照来测

本节成对探针适用于已选定可运行比较对象的任务。模板定义本身提供规范时，按上文模板交接验证，不为运行探针另找商业网站。

```bash
${WEB_UI_SKILL_DIR}/scripts/visual-budget <url> --reference <ref-url> \
  --ready '<selector>>=N' --reference-ready '<selector>>=N' \
  [--data-region <selector>] [--reference-data-region <selector>] [--viewport 1920x1080]
```

`--ready` 是**必需的**，而且是逐页面给的：它点名一个只有在真实内容到达之后才可能存在的锚点，而探针只统计它**可见的**匹配项。没有它，一个请求已经失败、却仍然渲染出了 nav、空状态和一张错误卡片的页面，会一路顺风地滑进正常读数——而那些读数看起来像一份极其克制的设计。跳过它需要显式加 `--no-ready-gate`，它会打印在输出里，并把那次运行标记为未核实。

`--ready` 与 `--data-region` 是**调用方提供的语义前提，不是探针校准出来的东西**：是你在决定哪个区域承担这个页面的职能、以及哪个锚点意味着「内容到了」。探针每次运行都把这两个原样打印回来，正是为了让后来的读者能审计这些数字建立在谁的判断之上。

它会把你的页面与参照并排给出：重复元素计数（badge/pill/chip）、不同的饱和色数与色相桶数、不同的边框样式数、边框密度、radius family 的规模、以屏为单位的页面长度，以及穿过数据区的一条扫描线上的内容覆盖率。

视觉用量的离群判断、差异筛选与包装去重使用以下未校准参数；L1b 的结构检查另行报告，不能将整个工具说成只有一道闸：

- **极端离群**：某个重复的视觉元素达到**参照同类计数的 ≥10 倍，且绝对值 ≥50**。它只断言*「相对那个参照，这是极端的」*——从不断言*「这个页面不合格」*。
  - 那个倍数来自一个负例；那个下限来自观察到的正例区间的上端（48）。
  - 两者的组合有**已知的不连续**，假装没有正是一条阈值被人信任的方式：参照 0–4、你的页面 49，不触发（下限）；参照 5、你的页面 50，触发（只比见过的最高的好页面多两个）；参照 20、你的页面 199，不触发。
- **25% 的差异阈值**用于筛选需要强制作答的读数。`120 vs 100` 不进入该清单，不等于两者相同；参照为 0、本页非 0 时仍算差异。
- **包装面积比 1.8**决定嵌套徽章去重：祖先面积与子项面积之比不超过它时视为包装。它影响离群计数，两侧比较须使用同一取值。

这四项可用 `--outlier-multiple` / `--outlier-floor` / `--diff-threshold` / `--wrap-area-ratio` 覆盖，工具每次都会输出；报告保留本次实际值及调用方选择器。不要凭手感修改它们，也不要把当前默认当作已校准的质量界线。

与参照不同的指标仍须解释。程序只对 `REPORT_ONLY` 中被上述差异判据选中的指标强制作答，缺非空答复时以 `incomplete`（退出码 4）结束；重复元件计数另走离群判断。未进入强制答复清单不等于没有差异，不能据此称所有差异都已解释。程序只验答复非空，不验理由成立，退出码 0 也不代表页面质量通过。

**在承担这个页面职能的那个区域里取读数，用它的读者实际使用的宽度。**整页或首屏的聚合会把问题平均掉：在引出这一切的那个页面上，首屏的数字*好过*两个受欢迎的参照（宽度 0.975、4 种颜色、11 个带边框的盒子），而四屏之下的指标表里有 1721 个 badge 和 1979 条边框。

**每一个页面级的聚合都需要一道渲染就绪闸。**一个没渲染出来的页面读起来就是一个极其克制的页面——实测：同一次普查在数据尚未到达的页面上报出「2 种饱和色、14 个带边框的盒子、5 种边框样式」，数据到了之后报的是「4 种颜色、209 个盒子」。`page-repetition` 在同一个 session 里踩了同一个坑：它只数了那个页面 72,885 个字符中的 465 个，然后报 **pass**。把闸挂在一个只有在内容存在之后才可能为真的东西上，并报 `unresolved` 而不是一个数字。

## L1b —— 三个完全不需要校准的读数

这三项不使用参照侧的用量阈值。`visual-budget` 单独报告它们：前两项触发结构检查时退出码为 `6`；第三项重复文字只报读数，不触发该退出码。它们与相对离群（退出码 `1`）分开解释。

### 1. 一个重复的结构必须*完全一致地*重复

当同一个块沿页面出现很多次时，同一列在各实例中应保持相对本表左缘的偏移一致，便于读者沿同一结构查找列；这不要求并排表格的屏幕绝对坐标相同。

测量方式：同一个表头标签相对**本表左缘**的不同 x 偏移数，按*（标签、列数、容器 class）*分组，`> 1` 触发结构检查。不是 viewport 绝对 x；并排放置的同构表可以从不同位置开始。分组避免把两族不同布局混在一起，不能把这个计数扩大成所有表格必须共享屏幕坐标的要求。

常见成因是 `table-layout: auto`：每张表都按自己最长的内容去定第一列的宽度，下游每一个值列都继承了这份晃动。在一个真实页面上实测：同一个表头出现在 **8 个不同的 x 上，跨度 542px**。

### 2. 任何会展开的东西都必须显示出它会展开，以及它当前的状态

测量方式：某个 `<details>` 的 `<summary>` 在**展开与收起时渲染完全相同**——探针会切换 `open`，对该 summary 的伪元素、transform、背景图与图标子元素的签名做 diff，然后把先前的状态恢复回去。**`> 0` 就是缺陷。**常见成因是看不见的：给 `<summary>` 设 `display: flex` 或 `grid` 会静默移除浏览器默认的那个三角，因为那个三角依赖 `display: list-item`。什么错都不报；只是那个 affordance 不再存在了。在一个真实页面上实测：**128 个折叠里有 92 个**完全没有标记。

**判据是「有没有东西随状态变化」，不是「有没有图标」**——这项检查更早的两个版本测的是一个标记的*存在性*，两个方向上都错了，而且各自都被外部 review 用一个具体案例抓到：

| 当时的写法 | 误报 | 漏报 |
|---|---|---|
| 只有 `::before` 有 content | `::after` 画的箭头、`<svg class=chevron>`、用背景图做的标记 | — |
| 上述任一图形存在 | `summary::after{content:"";border-right;border-bottom}` —— 在一个**空的**伪元素上用*边框*画出来的箭头，也是最常见的写法 | 一个与展开无关的头像 `<svg>`，会让一个**毫无** affordance 的页面通过 |

存在性不是读者使用的那个性质。他们用的是它*动了*。

### 3. 重复的文字不是噪声——它是一个从未被做出的分层决定

测量方式：叶子元素中同一个字符串出现的最高次数。这里**没有阈值**，也不该有；这个数字是一次提示，不是一个裁决。在一个真实页面上实测：一句 12 个字符的注解被打印了 **465 次**。

对每一处重复都问一句：**这句话实际上属于哪一层？**四个答案基本覆盖了全部：

| 重复的东西是…… | 它真正的层 | 那看起来是什么样 |
|---|---|---|
| **列**的一个属性 | 表头 | 在 `<th>` 里说一次，从单元格里删掉 |
| 某个**状态的注解** | 一条图例 | 单元格保留一个紧凑的 token（`N/A`、`未记录`）；那句话进一条图例，外加每个单元格的 `title` |
| **行所指对象**的一个属性 | 那一行，按需展开 | 一个 `ⓘ` 折叠——一次点击可达，不出现在默认界面上 |
| 一个标记，标的是**值本身已经说过**的事 | 哪一层都不属于 | 删掉它。一个装着数字的单元格，不需要再配一个写着「它产出了一个数字」的 badge |

**这些做法里没有一个字必须被删掉。**这正是重点，也正是分层与截断的区别所在：需要那句话的读者离它只有一次 hover 或一次点击，不需要的读者得到的是一个可以扫读的页面。

**两个坑，实践中都踩过：**

- **把重复缩短不等于把它去掉。**把一句 12 词的注解换成一个 6 词的标签、印 270 次，仍然是 270 次重复。如果答案是「按需」，那么那个 affordance 应该是一个带 `title` 和读屏标签的图标——不是一个图标再加一段说明文字。
- **层是按语义选的，不是按它省下多少墨。**最便宜的那一层往往是错的。一个恰好在这一批数据里保持不变的事实，并不*因此*就成为这一批的属性——见下文「宣称它已经修好之前，先验证」中「一个被挪到错误 scope 的层读起来是干净的」。问一句「如果数据变了，这个会不会跳层？」如果会，那一层就是错的。

**什么不得被折叠**：任何属于*警告*的东西。一个块可不可以折起来收走，取决于一个从不打开它的读者会不会仍然被误导——不取决于它是不是文字。两个输出「partially synced」与「measured at unknown time」的块被折进了一个收起的说明里，于是页面继续画着过期的指标数字，而完全没有任何信号。

## L2 —— 参数

按本次范围明确适用参数；取值与合格条件由本次有效设计决定，未规定部分沿用项目可用规则。下表用于核对角色、关系和实际效果；具体色相、阴影层数与动效方案留在具名实例中，不作为通用要求。

| 参数 | 需要明确什么 | 核对依据 |
|---|---|---|
| **Type ramp** | 各文字角色的字号、line-height、字重与 letter-spacing | 与有效设计一致，实际内容可读且层级可辨 |
| **Spacing ramp** | 间距尺度及其适用关系 | 同类对象节奏一致，例外有实际布局依据 |
| **Density** | 控件高度、行高与区块节奏 | 字体、间距和实际内容共同支持本次阅读与操作 |
| **Surface & line** | 表面与背景的区分方式及组合 | 需要区分的边界与分组在实际背景中可辨 |
| **Elevation ladder** | 存在哪些层级、每级承载什么及如何区分 | 层级表达与实际关系一致；阴影按有效设计采用 |
| **Radius family** | 圆角角色、嵌套关系及特殊形态 | 同类对象一致，嵌套关系在实际尺寸下协调 |
| **Motion** | 哪些状态需要过渡；采用时明确属性、时长、缓动与 reduced-motion 分支 | 状态变化可理解，动效服务任务且符合有效设计 |
| **Numerals** | 数字比较与对齐需求及其字形选择 | 实际数据能按任务需要阅读、比较与对齐 |
| **State matrix** | 可交互类可达的状态，含适用的 default、hover、focus-visible、active、disabled、selected | 状态可辨、键盘焦点可见；原生或定制样式均按实际效果核对 |
| **Color roles** | 语义角色及其取值 | 角色、对比和状态表达符合有效设计；基础色可采用中性或偏色方案 |

L2 内部的推导顺序——顺序错了就会逼出返工：

```
base unit → spacing ramp → type ramp → density → radius family → elevation ladder → motion → state matrix
                                          ↑
                                   color roles (independent)
```

**`type ramp` 在 `density` 之前，不是反过来。**`reference-instance.md` 写明控件高度由它的 line-height 加上垂直 padding 推出，而 `reading-instance.md` 在 type ramp 变化时会重算行高与控件高度。因此先决定 density 恰好会逼出这个顺序本来要防的那次返工。

[`design-ui/reference-instance.md`](design-ui/reference-instance.md) 是一个完整指定的 L2 实例（数据密集的技术界面）。[`design-ui/reading-instance.md`](design-ui/reading-instance.md) 是阅读档的实例，承载着一个控制台永远用不上的那些轴。**要做另一种外观，保留结构、替换取值**——将选定参数写入本次有效设计；批量执行见 [模板核验](batch-ui-verification.md)，不修改共享脚本的默认值来适配单个项目。

## 这个页面已经有系统了吗？——逐层去问

「我是在一个已确立的系统里工作」是大多数调用方的假设，而很少有人量过。在一个从来没有系统的页面上，「沿用现有的系统」意味着让浏览器的 UA 默认值继续做决定：加一个 `<ul>`、一行 CSS 都不写，UA 自己的 padding 与 margin 就落成了真实的间距值。

**逐层分别测量。它们各自独立地失败，而这次重建的全部要点就在于：L2 通过完全说明不了 L0 或 L1。**

- **L2**：先采集实际参数，再与项目已声明的角色和有效设计比较。`validate-visual-system.js` 默认仅输出诊断，不以通过率判断有无系统；模板任务按 [批量核验](batch-ui-verification.md) 的适用条件分流：多页或重复组件使用批量流程，单页局部改动定向检查受影响规则、状态与实际操作。旧 `reference-instance` profile 只保留历史示例检查，不代表其他风格的验收标准。
- **L1**：有可运行比较对象时跑 `visual-budget`，没有通过率——把数字挨着参照的数字读；模板路径按有效规则和目标真实内容观察用量与结构。
- **L0**：说出 form factor。如果说不出来，那就是答案。

```bash
agent-browser eval "$(cat ${WEB_UI_SKILL_DIR}/workflows/design-ui/scripts/validate-visual-system.js)"
```

它只能在一个已渲染的页面里跑——`node validate-visual-system.js` 会以 `ReferenceError: document is not defined` 失败。

**大多数 L2 的 `FAIL` 回答不了这个问题。**十四项检查里有十项可能在一个真正设计过的系统上失败：

| 检查项 | 在一个设计过的系统上什么时候会失败 |
|---|---|
| `neutrals tinted` | 这个实例选了不偏色的基础色——IBM Carbon 的 `#ffffff` / `#161616` 就挂在这一项上 |
| `shadows are multi-layer` | 聚焦环是 `box-shadow: 0 0 0 3px`，**而且运行时那个控件正处于聚焦状态**——上面那条朴素的 `eval` 量的是未聚焦状态 |
| `tabular numerals` | 散文里出现了一个裸数字。这个参数说的是**在一列里**的数字 |
| `no layout-property transitions` | 一个手风琴有意在动画 `height` |
| `line-heights are integers` | 这条 ramp 用的是逐角色的比值。计算值不携带出处 |
| `focus-visible defined` | 样式表里没有声明任何 `:focus-visible` 规则——包括一个没有任何可聚焦元素的文档 |
| spacing ladder、type-step count、weight tiers、motion coverage | 页面的梯子与 `EXPECTED` 不同。把页面自己的取值代进去重读；如果重建不出一条自洽的梯子，那次失败本身就是答案 |

运行条件会移动这些区间——一个自洽的页面在未聚焦时读到 8/12，在有控件聚焦时读到 8/13。把它们当作中间隔着一条宽缝的两个簇，而不是一把已校准的尺子。`UNCHECKED` 不是「不存在」的证据：一个只靠线条与色调来区分的系统，让阴影相关的检查无物可看；而只要有任何一张样式表是跨域的，`focus-visible` / `reduced-motion` 两项都会弃权。

[`scripts/calibration/`](../workflows/design-ui/scripts/calibration) 里存着产生这些读数的那些页面；复现方式与证据边界见[校准说明](design-ui/calibration.md)。

## 拿到一个参照——并**逐层**给它定资格

| 情形 | 这样做 |
|---|---|
| 已选定模板 | 按「Template-library 交接」实施；商业来源只做溯源，不进入下方寻找流程 |
| 点名了一个真实产品（「做得像 X 那样」） | 逐层给它定资格（见下），然后用 `scripts/probe-visual-system.js` 与 `visual-budget` 探测它 |
| 点名了一个公开发布的设计系统 | L2 直接取它文档里的 token 取值；L0/L1 去探测它的文档站 |
| 这个界面是一份要从头读到尾的文档 | [`design-ui/reading-instance.md`](design-ui/reading-instance.md) |
| 既没有所选模板，也没有其他设计依据 | 按下文寻找适用参照 |

**定资格是逐层的，一个参照可以在某些层合格、在另一些层不合格。**这不是一次精细化；它是对一次有记录的失败的修复。一个被用户明确点名为参照的新闻站点被探测之后，**L2 得 0.417，并被写成「没有系统，不要再选它当参照」**——而与此同时用户一直想要的正是它的构图与它的克制。他是对的，是那次定资格错了：这个页面是 **L0/L1 合格、L2 不合格**。一个参照只给一个裁决表达不了这一点，而把整个页面丢掉，丢掉的正是他实际在指的那些层。

把每一层的裁决连同产生它的读数，分别记进 [`design-ui/chosen-references.md`](design-ui/chosen-references.md)。一个从未被检查过的层，记成从未被检查过——而不是记成不存在。

**在同一次运行、同样的条件下同时探测参照与你自己的页面**，才使两者可比；一个被描述出来的参照，是在跑的那个参照的有损投影。有参照在场时，比较由 `${WEB_UI_SKILL_DIR}/references/web-ui-observation.md` 管辖。

### 复用已选参照，缺项再寻找

**先问：这个界面是不是一次性的**——一个调试页、一个没人会再回来的一次性产物？那么下面这些一条都不用：从 `design-ui/reference-instance.md` 出发，替换 color roles 与字体。此后的一切都是为一个会长期存在的页面写的。

1. **复用同产品的有效选择**：当前任务已点名参照时沿上表处理；否则查 [`design-ui/chosen-references.md`](design-ui/chosen-references.md)，按受众与场景匹配。用户为**同一个产品**作出的决定仍适用、且未要求更换时，直接沿用，不强制搜新或重选。其他产品的记录只作候选。复用的是选择，不是旧测量：逐层资格及对齐任务的本轮同条件实测仍按上文执行。
2. **只为待选层搜候选**：无可沿用的匹配、用户要求更换，或对应层资格失效时，再搜索该层的候选；不连带重开其他有效层的选择。候选发现按 [宿主与执行约定](portable-runtime.md)「发现候选的检索」，不把既有记录当完整候选集，也不宣称检索穷尽。
3. **新选择交用户裁决**：把候选、取舍、推荐项与理由交用户（`AskUserQuestion`，按用户级 Surface Choices）。subagent 把候选、取舍、推荐及实测特征交回 caller，明确该选择仍待裁决。
4. **新增或改变选择时更新 `chosen-references.md`**，逐层附实测依据；单纯沿用不重复写一份。当前任务的比较读数进入本次记分卡；未用卡时随本次观察报告交付，不因此省略实测。

需要新选的层没有合格候选，或用户明确拒绝全部候选时，该层从 `reference-instance.md` 出发并替换取值；其他层已有的有效参照继续沿用。仍在等待裁决不等于拒绝。

## 宣称它已经修好之前，先验证

依次核对下列项目：第 0 项按上述记分卡适用性执行，其余项用于本工作流的设计验收。已有本次对应对象、条件与版本的有效检查可直接引用，不为这张清单再跑一份；页面、条件或证据失效时补验。对齐任务的参照侧本轮复测要求仍保留。报告实际观察与未核实项，不能把探针完成等同于设计完成。

0. **使用了记分卡时重填并报告全卡**，按 `${WEB_UI_SKILL_DIR}/references/web-ui-dimension-rubric.md` 的 `refill` / `deliver`，含 `未取得` 与 `不判定` 及其原因。非对齐任务未用卡时跳过此项，不补造表格。

1. **L0 —— 重述 form factor，并拿 shell 对照它检查。**一句话说清：这是哪一类界面，shell 是否匹配（nav 的位置、宽度行为、第一屏上有什么），以及——如果这个 form factor 正是本文件记为未经验证的那一种——把这一点说出来。**没有任何探针覆盖这一步。**
2. **L1 —— 视觉用量与结构。**模板路径按有效定义及真实内容验证信息主次、密度与展开行为；存在可运行比较对象时可用 `visual-budget` 并排解释差异。商业参照路径运行该成对探针，差异答复仍须成立，程序只检查非空。三个 L1b 对应读数按目标实际结构报告，无对象时说明不适用；不为取得它们强制寻找外部参照。
3. **L2 —— 按本次有效设计核对实际组件参数。**模板路径按 [批量核验](batch-ui-verification.md) 的适用条件选择检查方式：多页或重复组件核验使用该流程，交代 PASS / FAIL / UNCHECKED / NA 与声明范围；单页局部改动可定向检查受影响规则、状态与实际操作，无需为此建立整站清单。无模板时使用诊断采样与项目参数对照；不要把默认诊断或旧 profile 的通过率当作设计完成。
4. **看一眼页面。**没有任何检查能告诉你结果看起来对不对，而这些探针按构造就对整类整类的缺陷视而不见。

数字不会告诉你的四件事，每一件在这里都实打实地花掉了一轮：

- **一个被挪到错误 scope 的层读起来是干净的。**一个事实从单元格去重上提到行、再上提到表，两次都产生 0 泄漏、0 误触发、测试全绿——而两次都是错的，因为这个项目自己的记录把那个事实放在单元格 scope。**语义分层没有读数；只有一份契约或一个人能判它。**问一句「如果数据变了，这个会不会跳层？」——如果会，那一层就是错的。
- **为了密度而折叠东西不是免费的。**一个块可不可以被折起来，取决于**它是不是一条警告**，不取决于它是不是文字。两个输出「partially synced」「missing N」「measured at unknown time」「parse failed」的块被折进了一个收起的说明里，于是页面继续画着指标数字，而读者完全没有信号知道它们已经过期。
- **在一个评测界面上，「哪些控件默认可见」是观看条件的一部分。**把那个决定*哪些被测对象出现在页面上*的控件折叠起来，是对实验的一次改动，不是一次密度改进。
- **常驻导航必须在滚动之后测量。**只能证明某条 media query 分支生效了、以及没有东西溢出的读数，证明不了 nav 仍然可达；而 `inView` 也证明不了它没被遮挡——用命中测试。

然后对你刚刚调弱的任何东西检查对比度。把一个状态色从 warn 角色降级成低调的墨色，让一个 11px 的 badge 在它真实的背景上从 9.52:1 掉到 **3.87:1**——低于 AA——而 L1 与 L2 的检查没有一项去看对比度。
