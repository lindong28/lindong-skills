# 参照设计的观察、适配与复验

当用户以真实界面的动态、操作或整体展示方式作为设计依据，或从参照界面、已采用的产品设计提炼模板时使用。提炼按所选范围核视觉与行为；普通模板应用或局部修正按实际涉及的机制读取，不自动回访模板来源或审计全站。本档是可移植的共同方法，具体组件默认、产品数据和现场读数留在模板或项目。

## 从选择参照的理由确定观察

先保留用户为什么选这个参照、希望目标读者获得什么结果，再选择需要观察的区域和行为。用户已经指向动态或交互时，应研究这些机制，不能因为尚未观察到就把它们排除，也不能只从目标已有控件反推范围。未明确的细节由 agent 在任务范围内研究和提出适配，真正影响用户取舍的差异才提问。

实际操作参照，并观察操作前、变化中、结束后及相关的后续行为。时间驱动的组件还需在无输入时观察一个可辨认的周期；用户输入会影响后续行为时，继续观察输入结束后的状态。观察时长与采样间隔须足以辨认所讨论的变化，静态截图或“按钮能点”不能证明动态一致。源码或配置可帮助定位和解释，不能代替运行结果；无法访问或不足以判明时保留未核实，不把猜测写成参照规格。

按机制选择必要条件，不要求固定全矩阵。例如轮播需要区分自动推进、手动切换及其后续计时，展开组件需要区分展开、关闭及再次进入；涉及响应式结构时观察相应宽窄屏。参考内容、布局关系、操作结果和过渡表现分别取证，不能由其中一种推断其余都已采用。

## 形成适用于目标的设计

把观察接回项目同一份有效设计，说明相关机制采用、调整或不采用的结果及理由，并明确哪些是参照实测、哪些是目标选择、哪些仍未核实。调整应能解释它如何服务目标内容、读者任务或已有约束；“不是完全复刻”本身不能说明为什么省略用户看中的机制。无需清点参照全站或审批每个细节。

对采用的动态机制，设计须足以判断实际行为：触发和终止条件、变化过程及操作后的接续。具体时间、布局和控制方式来自本次依据与目标条件，不把某次案例的数值或控件排列升级为所有产品的默认。无参照读数但已有依据的目标设计可以继续，仍不得称为已对齐原站。

## 提炼为可复用模板

以选定来源的实际版本、用户认可的范围及其体验目的为基线，保留对该目的有作用的设计关系：组件提供什么能力、怎样呈现及组织操作、为何采用这种表达。只有功能名称不足以传达这些关系时，将所需的呈现与状态写进模板定义；不能因替代控件也能完成同一动作，就默认它保留了原体验。认可范围不明确时区分已知认可、观察和推导，不把整页的每个细节都变成不可变要求。

在已有提炼记录中说明相关特征如何保留、参数化、调整或不采用，以及目标任务、内容或约束上的理由。可复用的关系进入定义及代表性示例，品牌与业务实例由目标提供；具体控件形态和数值的默认及适用条件留在对应模板，不提升为跨组件规范。材料不足时保留未核实，合理适配无需逐项申请审批；真正改变用户已定取舍时按原授权边界处理。

## 双向核对

复验同时回答两个问题：实现是否兑现有效设计；有效设计是否仍兑现用户选用参照的理由和本次范围内的相关机制。第二问回到原请求与参照观察，不能只拿自己删减后的清单验自己。差异说明留在同一任务记录，不新增独立审批或固定审查轮。

模板提炼将这两个问题落到来源、定义和实际运行示例：在可比状态下回看来源，核对定义是否漏掉影响目标的设计关系，以及示例是否兑现定义。定义遗漏不能靠示例自洽通过；示例中保留的承重设计也须让仅消费定义的下游取得。页面预览、下载示例和应用／审核入口共用当前定义，分别核本次受影响的消费路径。源码与结构检查辅助定位，不能代替真实呈现与操作；只提供分析建议不算完成模板产物验收。

在目标实际入口重现相关操作序列和时间过程；比较运行页面时固定可比条件，记录实际结果及合理差异。一次终态截图不能证明转场，计时器存在不能证明自动播放，点击后的切换不能证明接下来仍会自动推进。验收发现遗漏时回到观察或适配决定修复；范围外差异不自动成为缺陷。

本次读数只支持已观察的对象、条件与状态，不证明其他组件或未来 agent 必然正确。若要检验方法能否被 agent 主动使用，另用不附参考答案的普通任务输入，从正式入口执行；提供了答案后的检查只能算有提示复核。
