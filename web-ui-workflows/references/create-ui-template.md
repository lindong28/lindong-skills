# 从设计依据创建 Web UI 模板

将真实参照或已采用产品设计中可复用的部分沉淀为模板，使后续 session 仅凭模板就能应用和审核，不必重新访问来源网站。视觉风格、场景和组件模板都可独立创建；第二产品验证是可选输入，不是入库前置条件。

## 输入与职责

从请求取得参照网站及观察范围，或实际产品、有效设计及验证证据，再确定希望提炼的范围、模板仓位置和已授权产出。已有路径与访问权限直接复用，只补问会改变结果的缺失信息；来源账号和访问方式留在任务记录，不写入通用 skill 或公开模板。用户只要求研究时交付分析，不自动写入模板。

只应用已有模板走 [apply-ui-template](apply-ui-template.md)；参照网站改造指定产品走 [adapt-reference-ui](adapt-reference-ui.md)，由它按需回传提炼任务。读取、分类、规则合并和入库维护的权威为 [manage-ui-templates](manage-ui-templates.md)；独立组件样式按 [组件样式与选择](component-styles.md) 接入同一目录，不另建 catalog、模板副本或发布机制。

创建前按 [收录依据](manage-ui-templates.md#收录依据) 判断具体模式，逐个覆盖拟独立选择的变体。来源与发布批准分别判断；产品交付不以创建模板为前提，通用规则留模板，产品事实留项目。

## 创建或更新

从参照或已采用产品设计提炼时，在编写规则前读取 [参照设计的提炼与双向核对](reference-behavior-adaptation.md#提炼为可复用模板)，并在模板侧验证时沿同一基线复验；已有匹配观察直接复用。该方法承接来源到定义、定义到运行示例的设计保留与适配判断，下面的构建和一致性检查不替代它。产品验证来源须说明具体版本、覆盖的任务／状态及限制，未验证的推导不冒称已获认可，产品认可也不替代模板发布批准。

| 环节 | 产出与边界 |
| --- | --- |
| 查现有模板 | 读取模板仓规则与 `library/webui/references/admission.md`，按 manage 的入口查询当前定义。先判断复用、更新或新增：已有模板能承载的直接完善当前条目；新增须有独立复用价值，风格与场景均适用。 |
| 观察真实参照 | 先按用户选择参照的理由定位具体页面或状态，再使用 `agent-browser` 和 [web-ui-observation](web-ui-observation.md) 确认其中实际呈现了要借鉴的内容，观察代表组件和安全可展开状态；未取得匹配页面时报告缺口，不以同一产品的其他页面替代本次参照。记录具体入口、与选择理由对应的观察证据及未核实项；来自 adapt 或本任务的匹配证据可复用，缺口才补查。认证受阻按 [运行与依赖](portable-runtime.md) 的认证边界处理，替代材料与推断不得称为真实操作。 |
| 任务设计来源 | 从用户已采用或明确认可的产品设计提炼，核对实际产品与覆盖范围；不将 agent 验收写成用户认可。尚无可信依据的设计可以用于本次产品探索，不收进模板库，也不另建候选层。此行与真实参照行按实际来源执行。 |
| 提炼规则 | 按 [UI 规则归属](ui-rule-ownership.md) 区分视觉、场景、通用阅读原则和产品事实。风格描述可跨页的字体、颜色角色、间距、密度、表面和组件状态；场景描述读者任务、信息结构、组件关系、交互及适用的数据条件。产品特有业务留在产品，无可信依据的独立设计扩展不进入正式定义。 |
| 完成模板 | 沿模板仓当前格式更新定义、必要的共享基线、代表性示例及应用／审核 Prompt。承重规则、适用范围和限制写入定义，示例展示组合和状态；只保留有复用或维护用途的来源引用，让消费者无需原站或私有观察记录也能执行。应用与审核引用同一当前定义，不复制一套规则进 skill。 |
| 模板侧验证 | 按目标仓现有校验和构建入口检查定义、依赖资产、页面、API 与复制文本的一致性；以真实浏览器使用示例和复制入口，核对所声明规则的呈现及交互。覆盖范围按模板类型与实际声明确定，未覆盖部分明示；不以 build 成功替代视觉验证，也不以示例可用宣称产品应用成功。 |
| 入库与交付 | 回到 manage 的维护与目标仓发布流程，完成已授权的提交、入库及发布。收录依据成立后，按目标仓要求准备固定开发快照并取得必要发布批准；已有适用授权不重复询问。源网站被认可不等于所有新内容已批准。 |

机器可测规则采用模板仓已有规范；项目定位器与状态操作留给应用项目，通用批量执行复用 [batch-ui-verification](batch-ui-verification.md)，不因创建模板而建立新的检查框架。尚无产品绑定时不宣称已经完成产品级批量核验。

用户同时授权产品应用时，向 `apply-ui-template` 交付当前模板身份、实际定义来源及目标范围；需要继续参照驱动的功能改造时回到 `adapt-reference-ui`。应用发现的通用缺口经 manage 更新当前模板，项目例外留在项目，不强制每次创建后改造一个产品。

创建或更新场景时，按 [维护的层级放置判据](manage-ui-templates.md#维护) 确定顶层场景、子页面或模块，交付相应父子归属；不因来源网站多了一个 URL 就新增顶层模板。

## 交付

交代模板 ID、类型与实际路径，复用／更新／新增的结果，真实观察与推断的边界，模板侧验证范围及未核实项，以及开发快照、入库、提交、线上发布的实际状态。用户未要求产品应用时明确本次止于模板；执行过应用时另报目标产品证据，用户认可也独立记录。沿用任务和模板仓既有记录，不新建平行账本。
