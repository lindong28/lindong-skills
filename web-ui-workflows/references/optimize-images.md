# 优化网页图片

本指南是 `web-ui-workflows` 的按需执行路径：在页面引入、替换图片（含 CSS 背景）或处理图片加载问题时使用。目标是在保留图片用途与可见质量的前提下减少等待；范围限于本次涉及的图片，不自动启动整站设计或性能审计。

输入是本次图片及其实际页面入口、显示用途与项目已有的画质／兼容要求；有参照站时同时使用其真实入口。先做下表的轻量检查，再决定是否需要优化，不以尚未测出的“大图”或“慢”作为入口条件。

| 决策点 | 执行要求 |
| --- | --- |
| 图片是否值得优化 | 查实际交付的格式、像素尺寸与字节量，结合页面显示尺寸和加载过程判断负担。加载失败时先区分请求、服务和解码问题；不能把压缩当作所有失败的修复。小图或已有合适产物且未见相关负担时，保留并结束优化分支。 |
| 交付哪个版本 | 保留源资产，按显示尺寸、像素密度及放大需求生成有收益的交付版本；尺寸差异确有收益时用响应式图片。选择编码与压缩程度时保留必要的细节、透明度、动画及兼容性，不统一指定格式、质量参数或字节上限。 |
| 何时加载 | 首屏关键图及时发现并加载，不能懒加载；仅对真正关键且有需要的图片提高优先级或预加载，预加载须匹配浏览器实际选用的资源，避免重复下载。屏外图片按用途延迟加载；预留显示空间，避免加载导致布局跳动。 |
| 怎样更新缓存 | 按项目已有构建／资源版本机制同步图片与引用，使已有缓存用户能收到新版本。发布时复用 `${WEB_UI_SKILL_DIR}/references/web-ui-observation.md`「条件式验收：缓存升级（N-1 暖缓存→N 普通重新加载）」的适用判据与流程。 |
| 是否可以交付 | 用真实浏览器检查本次涉及的桌面／手机显示、加载中的画面及加载完成后的细节。按 `${WEB_UI_SKILL_DIR}/references/web-ui-observation.md`「测量技术」取得冷／热加载读数，并把目标锚在图片：分清开始可见、完整加载和页面可用；只有最终截图或文件变小不能证明加载体验改善。 |

有参照站时按同一观测档比较真实入口；网络波动、未部署版本或取不到的读数如实限定结论。优化已满足当前用途、或继续处理没有可观察收益时停止；需要扩大到 CDN、服务器配置或其他资源时，按 [宿主与执行约定](portable-runtime.md) 定范围与下一步。

输出并入本次交付：采用或保留哪个版本及理由、字节变化、画质与加载观察、仍未覆盖的边界。复用现有构建工具和浏览器读数，不为每张图片建立新测试平台。

`communication-workflows publish-page` 的静态发布仍按它自己的 [image-optimization.md](portable-runtime.md#相邻工作流) 处理 staged publish root；该优化器的输入范围和决策流程不由本指南覆盖。
