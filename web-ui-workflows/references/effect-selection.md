# 按体验意图选择效果

新建、整体设计、模板应用及相关组件增改时，主动判断效果是否帮助读者理解内容、发现可操作性、追踪变化或建立阅读节奏；不用等用户说“加动画”。局部修复只判断受影响单元，复用已有决定。效果是场景、风格和组件之上的可选行为层，不设全局默认，也不要求每页都动。

## 选择与来源

先确定读者任务、访问阶段、真实内容、已有风格与输入方式，再比较静态呈现和少量有明确用途的候选。吸引探索与快速查数可能需要不同处理；不要由页面名称、关键词或效果热度直接决定。显式风格与项目约束优先，例如风格禁止悬停位移时，不因目录有此效果就加入；已有反馈足够时保持它。

效果目录浏览入口为 `https://prompts.aiplanet.live/webui/effects/`，定义入口为 `/api/webui/effects/v1/index.json`，详情为 `/api/webui/effects/v1/<id>.json`。任务给定开发快照或授权本地模板仓时，沿同版入口读取；本地权威为 `library/webui/effects.json`，可运行示例源在 `library/webui/assets/effects/`。以完整定义的用途、条件、排除项、过程、回退和来源说明判断，不只看名称或截图。详情的 `example_url` 用于隔离预览，`download_url` 提供独立 HTML 包；解压后的 `index.html` 可用定义中的 `example_sha256` 核对，浏览器预览的宿主脚本不属于原始示例。目录摘要绑定定义与可下载示例。

目录不可达或当前发布尚不含效果时，说明该来源未取得；继续依据项目有效设计、已核实参照和当前任务完成可独立完成的设计，不声称已采用目录模板，也不把失败改写为“没有合适效果”。没有匹配项允许保持静态或按已授权目标设计局部效果；可复用提炼仍沿模板维护入口，不能直接把一次尝试变成长期开启的默认。

将选择接入现有有效设计：作用对象、希望帮助的任务、采用或不采用的理由、实际来源及摘要、适配参数和检查范围。无需另建评分表或配置文件；不得把所有候选和无关检查变成每次任务的固定成本。

## 适配与实现

保留目标品牌、真实内容和真实动作，示例中的合成产品只说明机制。根据内容层次和布局确定移动对象，不对整张图片机械叠加同一效果。明确触发、进行、结束及中断后的状态；使动画可被新的操作打断，不积累位移或延迟反馈。不要用装饰效果冒充加载、成功或业务进度。

保持文字、数值、焦点与点击区域可读可操作；有指针的悬停增强不能成为触屏或键盘访问内容的前提。尊重 `prefers-reduced-motion`，为相关设备保留静态或非位移反馈。入场效果默认内容可见，失败时仍可读，避免首屏或任务关键信息等待。采用 CSS 即足够时不增加动画库；持续效果才处理可见性、暂停和清理，不为短暂反馈引入常驻循环。

## 验证与交回

从用户真实入口触发，观察动作前、动作中、结束后和打断／离开后的差异，再完成原任务操作。核对相关的鼠标、键盘、触屏、减少动态效果及渐进增强回退；只检查本次实际影响的条件，不用截图或最终 CSS 属性替代过程。例：卡片内层移动时文字与点击区域应稳定；一次入场在返回后不应重播；非动态场景也要验证静态反馈和真实动作。

报告采用或不采用及理由、实际运行读数和未核实边界。目录可浏览、示例会动、目标产品应用正确是不同结论；不把少量任务成功推广为所有页面、模型或转化收益。
