# 体验意图：从用户期待到设计依据

体验意图是：**面向特定用户和访问阶段，希望界面促成什么感受、理解与下一步行动。** 它帮助对齐需求、选择与优化模板、检验设计表达；场景仍描述任务结构，风格仍描述视觉语言，不新增互斥的模板类型或质量排名。

## 对齐与选择

从用户原话、项目定位和实际内容提炼主要体验意图，必要时保留次要意图及适用阶段。先复用已有上下文，只询问会改变设计的未知或真实取舍；已明确的局部修正沿已有设计执行，不补整份问卷。期望感受、需要理解的价值与下一步行动应相互支持，不能只剩“高级”“惊艳”等审美形容词。

选择时读取模板当前定义中的体验意图、适用人群与阶段、设计手段、前提及依据。词表和具体模板标注由模板库维护，缺失表示未标注，不等于不适用；根据实际正文继续判断，不能按模板名称补标签，也不能将父场景意图自动当作每个子模块的独立能力。

比较候选怎样帮助本次用户产生预期感受、理解所需信息并继续行动，说明匹配点、缺口和适配成本。素材、真实能力、设备、无障碍与运行成本是实现条件；模板标签和预览存在都不证明这些条件已满足。指定风格保持其已定范围，场景和结构仍需适配当前用户；没有充分匹配的模板时从任务和适用参照形成设计，不强套模板或停在 no-match。

视觉表现强度、信息密度与交互主动性可作为相对独立的表达维度，帮助解释同一意图的不同实现；它们不是必填问卷、分数或质量等级。按当前任务说明取值及代价，不把高强度、低密度或更多动效默认当作更好。若主次意图确实冲突，接回用户尚未裁决的取舍，不能从标签替用户排序。

## 设计与优化

把意图接入同一份有效设计：为谁、在哪个阶段、希望感受和理解什么、能继续做什么，以及哪些内容、结构、交互和视觉选择支持它。记录本次所选模板的依据与必要调整，避免另外维护一份只写形容词的意图说明。

例如“激发探索与试用”可由有辨识度且真实的成果预览、适量悬念、易理解的价值和低阻力开始入口共同支持；“快速找到并行动”可能需要紧凑导航、清楚的名称与搜索、更短的直达路径。两者可以在同一门户的不同区域或访问阶段共存；具体机制仍由内容、受众与约束决定，不把这个例子固化成所有页面的布局。

改善设计时先定位意图在哪一段失效：没有吸引继续看的内容、看不懂价值、试用条件不清、操作路径中断，或表达与用户期待不符。修改对应的内容或机制，再核整体关系；仅增加大字、渐变、动画或卡片数量不能代替这一判断。诱导、隐瞒条件和把演示冒充真实能力不属于达成体验意图。

## 验收与反馈

从正常入口实际使用，沿既有任务检查支持意图的内容与机制。复用已有“情绪历程与参与感”和设计表达检查，不另建评分体系；局部任务只核受影响部分。按证据分别交代：

| 证据 | 能说明什么 |
| --- | --- |
| agent 的设计自评与真实交互观察 | 价值能否理解、内容层级是否支持方向、入口与反馈是否可用，以及设计推导的理由；不证明目标用户已经好奇、信任或愿意付费 |
| 用户针对具体版本的审美反馈 | 该用户对该版本与范围的认可或异议；不自动成为所有用户偏好或长期模板批准 |
| 实际用户行为数据 | 在所测人群、时间与条件下发生了什么；点击不自动等于试用完成，行为相关性不自动证明设计因果 |

缺少后两类证据时如实保持未知，继续完成可观察的设计和操作验收，不编造转化率、吸引力分数或新增强制埋点。实际效果不符时回到同一意图和失败位置修正；反馈绑定所用模板内容、目标项目与具体版本，更新最窄的权威来源。单次项目效果不扩大共享模板的批准范围。
