# 参照产品改进

把用户认可的产品作为设计与交互参照，以目标产品的读者任务和业务约束判断适用性。借鉴范围包含信息组织、操作流程、状态反馈及适用的新功能，不限于样式；商业产品的认可不等于批准复制全部功能或改变目标产品的业务语义。

## 范围与输入

从请求和上下文取得参照产品及可访问入口、目标仓库／页面、读者任务、已有约束和本次产出范围。复用已确认信息，只补问影响执行的缺口。没有指定参照时先确定用户认可的对象，不自行固定成某个商业产品；仅有视觉对齐、现成模板应用或设计审核需求时，分别交给 [design-ui](design-ui.md)、[apply-ui-template](apply-ui-template.md) 或 [review-ui](review-ui.md)。只从网站创建模板而不改造产品时进入 [create-ui-template](create-ui-template.md)。模板的来源产品不自动触发本流程。

“先研究／给建议／别改”只交付能力对照与建议；要求优化并沉淀模板时，在授权范围内完成实现、验证及模板处置。需要分阶段接续时按 [运行与依赖](portable-runtime.md) 记录目标、下一步及验证读数，复用项目已有计划，不把每次调用都升级为跨项目计划。

## 从真实参照到目标产品

| 环节 | 必须解决的问题与交接 |
| --- | --- |
| 体验参照 | 使用 `agent-browser` 在授权范围内观察真实页面和相关交互，按 [web-ui-observation](web-ui-observation.md) 取得呈现、内容和响应证据。区分真实操作、截图／文档描述与推断；认证或访问受阻时按 [运行与依赖](portable-runtime.md) 的认证边界处理，保留未核实项，不把替代材料称为真实体验。 |
| 判断适用性 | 对本次范围内的相关能力说明参照如何工作、目标现状、采用／调整／不采用及理由，并指向观察来源。允许补充目标缺少的功能；业务语义、数据条件或用户拥有的取舍发生变化时交用户裁决，不以参照有该功能代替授权。 |
| 完成改造 | 选定一个可独立使用和验证的改造单元，向 `design-ui` 交付参照证据、目标任务、采用范围和业务约束，复用已有设计系统。必要的数据或后端支持按目标仓规则实施；不能只做无真实能力的操作入口，也不带入与任务无关的后端优化。 |
| 验证结果 | 在目标产品的真实入口核验阅读、交互与响应，使用 `design-ui`／`web-ui-observation` 的既有要求。区分实现、验证、用户认可与部署状态；已完成一个单元后按已授权范围接续，不把剩余执行变成重复确认。 |

参照产品的访问方式和本次账号／环境证据留在任务或项目记录，不进入通用 skill。实际操作仍遵守浏览器接管、目标状态变更及发布的授权边界。

## 提炼模板与回收经验

授权范围包含模板提炼时，向 [create-ui-template](create-ui-template.md) 交付已有参照观察、采用的设计、已验证目标场景、项目覆盖与限制；复用匹配证据，不要求为交接重新浏览。创建入口判断复用、更新或新增，视觉风格与场景均可独立提炼，入库与维护沿 `manage-ui-templates` 和模板仓规则完成。

交代本次模板处置，但不强制每次新增模板或把只改产品扩大为模板建设；仅复用、没有适合沉淀的部分或不在授权范围时说明。项目特殊数据和业务行为留在目标仓库，不为凑齐分类新增模板。

第二个产品的应用可检验哪些部分通用、哪些依赖首个产品，按用户请求或既有计划执行，不作为每次任务的强制前置。记录用户对具体内容与场景的反馈，不把当次使用成功当成跨项目长期批准；网站发布按模板仓授权处理。

## 交付

交代相关能力的采用结果及理由、目标产品的改动和真实验证、模板的复用／更新／新增结果及实际来源，以及未完成项的归属。仅研究任务交付对照和建议，标明未实施；其余任务分别说明本地实现、提交、发布与部署的实际状态。

具体对照、业务决定和验证证据复用本次任务／项目的记录载体；通用流程留在本 skill，模板内容留在模板仓，不另建平行账本或项目专属模板副本。
